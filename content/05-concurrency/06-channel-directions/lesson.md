У канала может быть направление. `chan<- T` разрешает только отправку, `<-chan T` — только получение. Стрелка стоит там, куда идут данные: в `chan<-` они входят, из `<-chan` выходят. Создают всегда двунаправленный `chan T`, а при передаче в функцию или возврате из неё он неявно сужается.

Направления — это документация, которую проверяет компилятор. Функция с параметром `<-chan T` не сможет ни отправить в канал, ни закрыть его. Генератор, возвращающий `<-chan T`, гарантирует, что владелец канала — он один: только он пишет и только он закрывает.

## Как это в C#

- `Channel<T>` в .NET разделён на два объекта: `ChannelWriter<T>` и `ChannelReader<T>`. Передать в метод только `Reader` — то же, что передать `<-chan T`. В Go это не отдельные объекты, а один канал с более узким типом.
- Генератор `IAsyncEnumerable<T>` с `yield return` ближе всего к функции, которая возвращает `<-chan T` и пишет в него из горутины. Разница: `yield` ленив и работает по запросу, а горутина-генератор выполняется параллельно и забегает вперёд на ёмкость буфера.
- Приведение `(ChannelWriter<T>)` обратно к `Channel<T>` в C# невозможно, и в Go тоже: из `<-chan T` двунаправленный канал не получить никаким преобразованием.

## Ловушки

### Генератор, возвращающий `chan T`

```go
func numbers() chan int { // вызывающий может отправить или закрыть
	ch := make(chan int)
	go func() {
		defer close(ch)
		ch <- 1
	}()
	return ch
}

ch := numbers()
close(ch) // компилируется — и роняет генератор: send on closed channel
```

Возвращайте `<-chan int`: тогда `close(ch)` у вызывающего — ошибка компиляции `invalid operation: cannot close receive-only channel`.

### Обратного преобразования нет

```go
func drain(in <-chan int) {
	ch := (chan int)(in) // ошибка компиляции: cannot convert
}
```

Если функции нужно и читать, и писать, — она должна получить `chan T`. Сужение направления — односторонний процесс.

### Куда относится стрелка

```go
var a chan<- chan int   // только отправка; элементы — chan int
var b chan<- <-chan int // только отправка; элементы — <-chan int
var c chan (<-chan int) // двунаправленный; элементы — <-chan int
```

Стрелка `<-` прилепляется к самому левому `chan`, какому только может. Если нужен другой смысл, расставьте скобки.

## Задание

Напишите три функции-стадии, которые собираются в цепочку `Sum(Filter(Range(from, to), keep))`.

- `Range(from, to int) <-chan int` отправляет числа `from, from+1, …, to-1` по порядку и закрывает канал; при `from >= to` канал закрывается сразу, без значений.
- `Filter(in <-chan int, keep func(int) bool) <-chan int` пересылает из `in` только те значения, для которых `keep` вернула `true`, сохраняя порядок; закрывает свой канал после закрытия `in`.
- `Sum(in <-chan int) int` читает `in` до закрытия и возвращает сумму; для канала, закрытого без значений, — 0.

Требования:

- `Range` и `Filter` возвращают канал сразу, не дожидаясь конца данных: работу выполняют горутины;
- `keep` вызывается ровно один раз для каждого значения;
- после того как `Sum` вернулась, ни одной запущенной стадиями горутины не остаётся.
