`go f()` не возвращает ничего похожего на `Task`: ни результата, ни способа дождаться завершения. Если горутин много и нужно просто дождаться, пока все закончат, используют `sync.WaitGroup` — счётчик задач. `Add(n)` увеличивает его, `Done()` уменьшает на единицу, `Wait()` блокируется до нуля.

С Go 1.25 есть `wg.Go(f)`: он сам делает `Add(1)`, запускает `f` в новой горутине и вызывает `Done`, когда `f` вернётся. Это теперь рекомендуемая форма; пара `Add`/`Done` по-прежнему нужна, если задачу запускаете не вы или она завершается не возвратом функции.

Результатов `WaitGroup` не собирает. Самый простой способ — заранее выделить срез длины `n` и дать каждой горутине писать в свой элемент: разные элементы — разные участки памяти, гонки нет, порядок совпадает с порядком входа. Нужны ещё и ошибки с отменой остальных — это `errgroup`, ему посвящён отдельный урок.

## Как это в C#

- `await Task.WhenAll(tasks)` — ближайший аналог `wg.Wait()`. Но `WhenAll` собирает результаты и исключения, а `WaitGroup` — только счётчик; результаты пишут в срез, ошибки — отдельно или через `errgroup`.
- `CountdownEvent` в .NET устроен так же, как `WaitGroup`: `AddCount`, `Signal`, `Wait`. Разница — у `WaitGroup` нулевое значение готово к работе, конструктор не нужен, а после обнуления счётчика его можно использовать снова; `CountdownEvent.AddCount` на нуле бросает исключение.
- Исключение в `Task` попадёт в `WhenAll`. Паника в горутине роняет весь процесс — `Wait` её не перехватит. Документация `wg.Go` прямо требует, чтобы `f` не паниковала.
- Замок в C# — ссылочный объект: копия структуры с полем-замком указывает на тот же замок. `WaitGroup`, `Mutex` и другие типы `sync` — значения, их копировать нельзя: копия — независимый счётчик (такое ловит `go vet`).

## Ловушки

### `Add` внутри горутины

```go
for _, job := range jobs {
	go func() {
		wg.Add(1) // может выполниться уже после wg.Wait()
		defer wg.Done()
		process(job)
	}()
}
wg.Wait() // может вернуться сразу: счётчик ещё ноль
```

Горутина может не успеть стартовать до `Wait`, и тот увидит ноль. `Add` вызывают до `go` — в той же горутине, что потом ждёт. С `wg.Go` эта ошибка невозможна.

### Копия WaitGroup

```go
func worker(wg sync.WaitGroup) { // копия
	defer wg.Done() // уменьшает счётчик копии
}

wg.Add(1)
go worker(wg)
wg.Wait() // ждёт вечно
```

`go vet` предупреждает: `worker passes lock by value: sync.WaitGroup contains sync.noCopy`. Передавайте `*sync.WaitGroup`, а лучше вообще не передавайте: вызывайте `Done` в замыкании, а функция-работник пусть ничего не знает о синхронизации.

### Забытый `Done`

```go
wg.Add(1)
go func() {
	if err := step(); err != nil {
		return // Done не вызван — Wait никогда не вернётся
	}
	wg.Done()
}()
```

Ставьте `defer wg.Done()` первой строкой горутины — тогда ранний `return` и паника его не обойдут. Если счётчик уйдёт в минус, `Add` паникует: `sync: negative WaitGroup counter`.

## Задание

У `WaitGroup` нет ожидания с таймаутом — `Wait` блокируется, пока счётчик не дойдёт до нуля, и прервать его нельзя. Напишите две функции:

```go
func WaitTimeout(wg *sync.WaitGroup, d time.Duration) bool
func RunAll(d time.Duration, tasks ...func() error) ([]error, bool)
```

`WaitTimeout` ждёт, пока счётчик `wg` дойдёт до нуля, но не дольше `d`:

- возвращает `true`, как только счётчик стал нулём (если он ноль уже при вызове — сразу), и `false`, если за `d` этого не случилось; `false` — не раньше, чем через `d`;
- счётчик не меняет: не вызывает `Add` и `Done`, после возврата `wg` используется как обычно;
- если для ожидания вы запускаете горутину, после возврата `false` она не должна повиснуть навсегда: она обязана завершиться, как только счётчик дойдёт до нуля.

`RunAll` запускает задачи и ждёт их с таймаутом:

- каждая задача вызывается ровно один раз, каждая — в своей горутине, все одновременно;
- если все задачи завершились за `d` — возвращает срез длины `len(tasks)`, где `errs[i]` — результат `tasks[i]`, и `true`; без задач — срез длины 0 и `true`;
- иначе — `nil` и `false`, не раньше, чем через `d`. Задачи при этом продолжают работать (остановить горутину снаружи нельзя), но срез, в который они пишут, наружу не отдаётся; горутины `RunAll` завершаются, когда завершатся задачи.

`wg` не `nil`, `d > 0`, задачи не паникуют.
