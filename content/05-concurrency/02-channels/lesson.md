Канал `chan T` передаёт значения типа `T` между горутинами. `ch <- v` отправляет, `v := <-ch` получает. Канал из `make(chan T)` — небуферизованный: у него нет места для хранения, поэтому это точка встречи. Отправитель блокируется, пока не придёт получатель, получатель — пока не придёт отправитель. Когда операция завершилась, обе стороны знают, что передача состоялась.

Поэтому канал — это и транспорт данных, и синхронизация одновременно. Девиз Go: «не общайтесь через общую память — делитесь памятью через общение». Вместо общей переменной под мьютексом одна горутина передаёт значение другой, и в каждый момент им владеет кто-то один.

## Как это в C#

- Ближайший аналог — `System.Threading.Channels`. Но `Channel.CreateUnbounded<T>()` никогда не блокирует запись, а у `Channel.CreateBounded<T>(n)` минимальная ёмкость — 1. Канала-рандеву ёмкостью 0, как `make(chan T)` в Go, там нет.
- `await reader.ReadAsync()` освобождает поток и продолжается в колбэке. `<-ch` в Go просто блокирует горутину — код остаётся линейным, без `async` и `ValueTask`.
- В C# канал — объект из библиотеки. В Go это встроенный тип со своим синтаксисом (`<-`), его понимают `select` и `range`. Типизирован он так же строго, как `Channel<int>`: отправить `string` в `chan int` не даст компилятор.
- `BlockingCollection<T>` блокирует поток ОС. Заблокированная на канале горутина потоком не владеет — поток в это время выполняет другие горутины.

## Под капотом

Канал — указатель на структуру `runtime.hchan` в куче. В ней счётчик `qcount` и размер `dataqsiz` кольцевого буфера `buf` (у небуферизованного канала он нулевой), индексы `sendx` и `recvx` и две очереди ждущих горутин — `recvq` и `sendq`. Каждая ждущая горутина представлена записью `sudog`: кто ждёт и где лежит (или куда положить) значение. Все поля защищены мьютексом канала.

Отправка сначала ищет ждущего получателя — и копирует значение прямо ему в стек. Если получателя нет, но есть место, — кладёт в буфер. Иначе встаёт в `sendq` и засыпает. Получение устроено зеркально. `close` будит сразу всех ждущих. Сценарий ниже показывает буферизованный канал ёмкостью 2 — в нём видны все ветки.

## Ловушки

### Deadlock в одной горутине

```go
ch := make(chan int)
ch <- 1          // никто не получает — main блокируется навсегда
fmt.Println(<-ch)
```

Программа падает с `fatal error: all goroutines are asleep - deadlock!`. Рантайм замечает, что все горутины заблокированы и разбудить их некому. Но детектор срабатывает, только если спят **все**: если где-то крутится хоть одна живая горутина (сервер, таймер), зависшая половина программы останется висеть молча.

### nil-канал блокирует навсегда

```go
var ch chan int // nil: забыли make
go func() { ch <- 1 }() // заблокируется навсегда
<-ch                    // и это тоже
```

Нулевое значение канала — `nil`. Отправка в него и получение из него не паникуют, а блокируют горутину навсегда. Создавайте каналы через `make`. Эта «вечная блокировка» пригодится в `select`: присвоив каналу `nil`, ветку выключают.

### Горутина, которую некому дочитать

```go
func first(urls []string) string {
	ch := make(chan string)
	for _, u := range urls {
		go func() { ch <- fetch(u) }()
	}
	return <-ch // остальные горутины навсегда застряли на отправке
}
```

Получили одно значение из нескольких — остальные отправители висят в `sendq` вечно и держат память. Это утечка горутин; детектор deadlock её не видит, потому что `main` жива. Получайте столько значений, сколько отправлено, или дайте каналу буфер на все значения.

## Задание

Напишите функцию `SumAll(sources []func() int) int`, которая вызывает все источники конкурентно и возвращает сумму их результатов.

Требования:

- каждый источник вызывается ровно один раз, в своей горутине; все вызовы идут одновременно — источник может ждать, пока не запустятся остальные;
- результаты передаются в вызывающую горутину через канал; общая переменная-сумма, которую горутины меняют сами, — гонка данных (тесты запускаются с `-race`);
- функция возвращается только после завершения всех источников, и после неё не остаётся ни одной запущенной ею горутины;
- для пустого или `nil` среза результат — 0.
