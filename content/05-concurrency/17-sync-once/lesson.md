`sync.Once` гарантирует, что функция выполнится ровно один раз, даже если `Do` одновременно вызвали сто горутин. Первая выполняет функцию, остальные ждут её завершения — и только потом `Do` возвращается. Поэтому всё, что функция записала, после `Do` видно без дополнительной синхронизации.

С Go 1.21 есть обёртки, которые избавляют от пары «глобальная переменная + `Once`»: `sync.OnceFunc(f)` возвращает функцию, вызывающую `f` один раз; `sync.OnceValue(f)` ещё и запоминает результат; `sync.OnceValues(f)` — пару результатов, обычно «значение, ошибка». Главное различие — паника: `Once.Do` считает паникующую функцию выполненной и больше её не вызывает, а обёртки запоминают панику и повторяют её при каждом вызове.

## Как это в C#

- `Lazy<T>` (по умолчанию `ExecutionAndPublication`) — это `sync.OnceValue`: фабрика вызывается один раз, остальные потоки ждут результата.
- `Lazy<T>` с фабрикой кеширует исключение и бросает его при каждом обращении к `Value` — так же ведут себя `OnceValue` и `OnceFunc` с паникой. А `Once.Do` после паники просто ничего не делает: поле, которое функция не успела заполнить, остаётся нулевым.
- Ошибку в Go возвращают значением, поэтому для «инициализации, которая может не удаться» берут `OnceValues` — он запомнит и значение, и ошибку. Повторной попытки, как у `LazyThreadSafetyMode.PublicationOnly`, ни один из вариантов не делает.
- `static readonly` поле и статический конструктор инициализируются рантаймом .NET один раз на тип. В Go аналог — переменная пакета или функция `init()`, но они выполняются при старте программы, а не лениво.

## Ловушки

### `Do` внутри `Do`

```go
var once sync.Once
func setup() {
	once.Do(func() {
		setup() // вложенный Do ждёт завершения внешнего — deadlock
	})
}
```

`Do` возвращается только после завершения функции. Рекурсивный вызов того же `Once` ждёт сам себя.

### Копия `Once`

```go
type client struct {
	once sync.Once
	conn *conn
}
func (c client) get() *conn { // получатель по значению — копия once при каждом вызове
	c.once.Do(c.dial)
	return c.conn
}
```

Каждый вызов работает со своей копией, и `dial` выполняется снова и снова. Методы с `sync.Once` (как и с `sync.Mutex`) объявляют на указателе; `go vet` ругается на копирование: `passes lock by value`.

### Неудачная инициализация навсегда

```go
var db *sql.DB
var once sync.Once
func get() *sql.DB {
	once.Do(func() { db, _ = sql.Open("pgx", dsn) }) // ошибка проглочена
	return db                                         // nil — и так до перезапуска
}
```

Второго шанса `Once` не даёт. Если ошибку нужно вернуть — `sync.OnceValues`. Если нужен повтор после ошибки — `Once` не подходит, понадобится мьютекс и флаг.

## Задание

Напишите обобщённый кеш, который загружает значение каждого ключа ровно один раз:

```go
func NewCache[K comparable, V any](load func(K) (V, error)) *Cache[K, V]
func (c *Cache[K, V]) Get(key K) (V, error)
```

Требования:

- `Get` возвращает результат `load(key)`; для каждого ключа `load` вызывается не больше одного раза за всю жизнь кеша — даже если `Get` с этим ключом одновременно вызвали много горутин;
- пока загрузка ключа идёт, другие вызовы `Get` с тем же ключом ждут её и получают тот же результат;
- ошибка тоже запоминается: повторный `Get` того же ключа возвращает то же значение и ту же ошибку, не вызывая `load`;
- загрузки разных ключей идут параллельно: медленный `load` одного ключа не задерживает `Get` других ключей;
- если `load` паникует, `Get` паникует с тем же значением — и при каждом следующем `Get` этого ключа, без повторного вызова `load`;
- `Get` безопасно вызывать из многих горутин.
