# Кейс: игровой сервер

Обзор модуля для показа команде: игровой сервер на Go, совместимый с базовым протоколом Minecraft Java Edition.

---

## TCP — поток байт, а не сообщений

- Пакеты по 10 и 30 байт могут прийти одним `Read` на 40 байт или по байту. Один `Read` — не один пакет.
- Границы задаёт протокол: кадр «VarInt длина → VarInt id → данные», как в Minecraft.
- Свой декодер VarInt: не длиннее 5 байт, без переполнения и неканонических форм; `binary.Uvarint` — другой формат.
- Длину кадра и строк проверяют до выделения памяти; декодер покрывают fuzz-тестом.

---

## Соединение — конечный автомат

- handshake → status или login → play. Id `0x00` значит разное в разных состояниях.
- Таблица «состояние × id → обработчик»; неизвестный пакет в состоянии — разрыв.
- Настоящий протокол — Java Edition 1.21.1 (767): фаза configuration, чанки с палитрами, Set Compression с лимитом распаковки.

---

## Игровой цикл: один владелец мира

| C# | Go |
| --- | --- |
| `lock` вокруг общего состояния | одна горутина владеет миром |
| `Channel.CreateBounded<T>`, `TryWrite` | ограниченный `chan Command`, `select` с `default` |
| `PeriodicTimer` | `time.Ticker` |

Тик — 50 мс, 20 TPS, фазы «ввод → обновление → рассылка». MSPT — сколько тик занял на самом деле.

---

## Ticker против накопителя

`time.Ticker` выбрасывает пропущенные тики. Цикл с накопителем держит сетку 50 мс, догоняет не больше нескольких тиков подряд, а лишнее отбрасывает.

## Медленный клиент не останавливает мир

```go
func (c *Client) Send(p []byte) bool {
	select {
	case c.out <- p:
		return true
	default: // очередь полна — клиент не успевает читать
		c.Close(errSlow)
		return false
	}
}
```

Две горутины на соединение: читатель и писатель. Тик в сокет не пишет; заблокированную горутину будит закрытие соединения.

---

## Тик без аллокаций

- 200 игроков по десятку срезов на тик — 40 000 объектов в секунду только на рассылку позиций.
- Сборщик без поколений размечает всю живую кучу, mark assist попадает в хвост MSPT.
- Предвыделение, срезы с `[:0]`, кодирование пакетов Append-функциями в переиспользуемый буфер.
- Проверка — `AllocsPerRun`, `-benchmem` и `-gcflags=-m`.

---

## Чанки и зона видимости

Мир делится на чанки 16×16, игрок видит квадрат (2r+1)² вокруг своего. При переходе границы шлют разность квадратов, события — только подписчикам чанка. Номер чанка — `math.Floor(x / 16)`: `int(x) / 16` для отрицательных координат ошибается. «Кто рядом» внутри тика ищет пространственный хеш, а не перебор всех сущностей.

## Не доверять клиенту

- Всё из сокета — заявление клиента, а не факт: сервер решает, что произошло в мире.
- Ведро токенов на тиках, а не на `time.Now()`.
- Проверка скорости с запасом на лаг и возврат на последнюю верную позицию; `NaN` проходит наивную проверку.

---

## Сохранение, тесты, масштабирование

- Снапшот — в тике (copy-on-write чанков), запись — в отдельной горутине, файл заменяют атомарно через `os.Rename`.
- Детерминированная симуляция: зерно, ручные тики, канонический порядок ввода, без `time.Now()` и обхода map внутри тика.
- Один мир — один процесс; масштабируют мирами и прокси в духе Velocity.
- Сервер из `labs/`: `docker compose --profile labs up -d --build gameserver`, подключение — `localhost` из клиента 1.21.1 или браузер.

---

## Что запомнить

- Кадрирование и лимиты — до разбора и до выделения памяти.
- Мир трогает одна горутина, связь с ней — ограниченные каналы.
- Медленного клиента отключают, а не ждут.
- Бюджет тика — 50 мс: без аллокаций, без сети и диска внутри.
