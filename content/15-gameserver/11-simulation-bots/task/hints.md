## Подсказка 1

Состояние: текущий тик, генератор `rand.NewPCG(seed, 0)` (не `rand.Rand` и не глобальный генератор — только его `Uint64()`), игроки `map[uint32]Pos` и занятые клетки `map[Pos]uint32`, отложенные вводы по тикам и журнал принятых вводов. `Submit` проверяет `Kind`, потом тик, и только принятый ввод кладёт и в очередь, и в журнал.

## Подсказка 2

`Step`: увеличить тик, взять вводы этого тика и **отсортировать** их по `(Player, Kind, DX, DZ)` — `slices.SortFunc` с `cmp.Or(cmp.Compare(...), ...)`. Порядок прихода и порядок обхода map не должны влиять ни на что: map обходите только там, где результат потом сортируется. Вход в полный мир (`len(players) == size*size`) и повторный вход проверяйте **до** обращения к генератору.

## Подсказка 3

Появление: `for { x := int32(r.Uint64() % uint64(size)); z := int32(r.Uint64() % uint64(size)); if свободно { занять; break } }` — сначала x, потом z. `Players` собирает срез из map и сортирует по `ID`; `Hash` пишет в `fnv.New64a()` буфер из `binary.BigEndian.AppendUint64(nil, tick)` и по каждому игроку из `Players()` — `AppendUint32` для ID, `uint32(X)`, `uint32(Z)`. `Log` — `slices.Clone` журнала, отсортированный тем же сравнением, но с `Tick` первым ключом. `Replay` — `NewSim`, `Submit` всего журнала, `Step` нужное число раз.
