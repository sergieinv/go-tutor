`defer f()` откладывает вызов `f` до выхода из текущей функции — по `return`, по концу тела или при панике. Обычный приём — закрыть ресурс сразу под строкой, где его открыли: `f, err := os.Open(p)`, проверка ошибки, `defer f.Close()`. Открытие и закрытие стоят рядом, и ни один из ранних `return` не забудет про закрытие.

У `defer` три правила, которые нужно знать наизусть: отложенные вызовы выполняются в обратном порядке, их аргументы вычисляются в момент `defer`, и привязаны они к функции, а не к блоку.

## Как это в C#

- `using` / `IDisposable` закрывает ресурс в конце блока. `defer` срабатывает в конце **функции**: в цикле `using` закроет ресурс на каждой итерации, а `defer` — только когда закончится вся функция.
- `finally` выполняет блок кода; `defer` откладывает один вызов функции. Нужно несколько действий — отложите замыкание: `defer func() { ... }()`.
- Несколько `using` освобождаются в обратном порядке — как и `defer`: последний отложенный выполняется первым.
- `Dispose` не возвращает ошибку. `Close() error` в Go возвращает, и при записи её нельзя терять — для этого есть именованный результат и замыкание в `defer`.

## Ловушки

### `defer` в цикле

```go
for _, p := range paths {
	f, err := os.Open(p)
	if err != nil {
		return err
	}
	defer f.Close() // закроется только при выходе из функции
	process(f)
}
```

На тысяче файлов кончатся файловые дескрипторы. Вынесите тело цикла в функцию — тогда `defer` сработает в конце каждой итерации.

### Аргументы вычисляются сразу

```go
start := time.Now()
defer log.Println("заняло", time.Since(start)) // ≈0: Since вызван в строке defer
defer func() { log.Println("заняло", time.Since(start)) }() // так правильно
```

Отложен только внешний вызов. Всё, что стоит в аргументах, считается немедленно. Замыкание же читает переменные в момент выполнения.

### Потерянная ошибка `Close`

```go
func save(path string, data []byte) error {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer f.Close() // ошибка записи на диск при закрытии потеряна
	_, err = f.Write(data)
	return err
}
```

При записи `Close` может сообщить, что данные не дошли до диска. Используйте именованный результат и замыкание, как в примере выше. Для файлов, открытых только на чтение, `defer f.Close()` без проверки — нормальная практика.

## Задание

Напишите функцию `UseAll(open Opener, names []string) error`, которая по очереди открывает ресурсы, использует и закрывает их.

```go
type Resource interface {
	Use() error
	Close() error
}

type Opener func(name string) (Resource, error)
```

Требования:

- ресурсы обрабатываются в порядке `names`: `open(name)`, затем `Use()`, затем `Close()`;
- одновременно открыт не больше чем один ресурс: каждый закрывается до открытия следующего;
- если `open` вернул ошибку, закрывать нечего — `UseAll` возвращает ошибку;
- если `Use` вернул ошибку, ресурс всё равно закрывается, а возвращается ошибка `Use`, даже если `Close` тоже упал;
- если `Use` прошёл, а `Close` вернул ошибку, возвращается ошибка `Close`;
- на первой ошибке обработка останавливается;
- возвращаемая ошибка начинается с `<name>: ` и оборачивает исходную через `%w`;
- для пустого `names` — `nil`.
