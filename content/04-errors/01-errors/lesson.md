В Go нет исключений для ожидаемых сбоев. Ошибка — обычное значение типа `error`, встроенного интерфейса с одним методом `Error() string`. Функция, которая может не справиться, возвращает ошибку последним результатом, а вызывающий код проверяет её сразу: `if err != nil { return ..., err }`.

Так путь ошибки виден в коде явно: по сигнатуре понятно, что функция может упасть, а по каждой строке — что происходит при сбое. Цена — многословность, и Go сознательно её платит.

## Как это в C#

- В C# сбой бросают исключением, и оно летит вверх по стеку, пока его не поймает `catch`. В Go ошибку возвращают как обычный результат, и каждый уровень сам решает: обработать, добавить контекст или вернуть выше.
- Сигнатура C#-метода не говорит, какие исключения он бросает. В Go последний результат `error` — явный признак, что вызов может не удаться.
- Брошенное исключение несёт стектрейс: его заполняет `throw`, и раскрутка стека стоит дорого. `errors.New("...")` и `fmt.Errorf(...)` — дешёвые значения без стектрейса: контекст добавляют текстом на каждом уровне.
- Аналог исключений в Go есть — `panic`, — но он для программных ошибок (баги, нарушенные инварианты), а не для «файл не найден». О нём — в уроке про panic и recover.

## Ловушки

### Проигнорированная ошибка

```go
n, _ := strconv.Atoi("12a") // ошибка выброшена в _
fmt.Println(n * 2)          // 0 — программа тихо работает с мусором
```

`_` молча отбрасывает ошибку: никакого исключения не будет, программа продолжит с нулевым значением. Если ошибку действительно можно игнорировать, напишите рядом комментарий, почему.

### Результат при ошибке

```go
n, err := strconv.Atoi("99999999999999999999")
fmt.Println(n, err != nil) // 9223372036854775807 true
```

При ошибке результат не обязан быть нулевым: `Atoi` при переполнении возвращает максимальное `int`. Соглашение Go — если `err != nil`, остальные результаты не читают. В своих функциях при ошибке возвращайте нулевые значения явно: `return 0, err`.

### Ошибка без контекста

```go
if err != nil {
	return err // «invalid syntax» — но где, в каком файле и какой строке?
}
```

Ошибка, прошедшая пять уровней без изменений, теряет смысл. Добавляйте то, что знает текущий уровень: `fmt.Errorf("строка %d: %v", i, err)`.

## Задание

Напишите функцию `ParseConfig(lines []string) (map[string]int, error)`, которая разбирает строки вида `key=value` в map.

Требования:

- пустые строки и строки из одних пробелов пропускаются;
- строка делится по **первому** `=`: в `a=b=c` ключ `a`, значение `b=c` (не число — ошибка);
- ключ и значение обрезаются по пробелам (`strings.TrimSpace`) по отдельности; пустыми они считаются после обрезки (`" = 1"` — пустой ключ, `"a = "` — значение не число); значение — целое число (`strconv.Atoi`);
- ошибкой считаются: строка без `=`, пустой ключ, значение, которое не число, повтор ключа;
- текст ошибки начинается с `line N: `, где N — номер строки с 1, дальше — описание на ваш выбор;
- при ошибке функция возвращает `nil` вместо map; разбор останавливается на первой ошибке;
- для пустого или `nil` входа возвращается пустая (не `nil`) map и `nil`-ошибка.
