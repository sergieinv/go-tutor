## Подсказка 1

Ищите каждое поле, которое одна горутина пишет, а другая читает без синхронизации: «быстрая проверка» `s.cfg == nil` вне мьютекса, `return s.cfg`, флаг `ready`, `hits++`. То, что `Reload` пишет под мьютексом, не помогает: читатель в `Config` мьютекс не берёт, и happens-before между ними нет. Счётчик проще всего сделать `atomic.Int64`.

## Подсказка 2

Текущую конфигурацию храните в `atomic.Pointer[Config]`: `Reload` — это `Store`, быстрый путь `Config` — `Load`. Если `Load` увидел указатель, он видит и все поля, заполненные до `Store`. Ленивую загрузку оберните в `sync.Once`, а результат `load` кладите через `CompareAndSwap(nil, …)`, чтобы он не затёр конфигурацию, которую уже опубликовал `Reload`.

## Подсказка 3

Отдельный флаг `ready` не нужен: закрытый канал и есть флаг. `MarkReady` — `once.Do(func() { close(s.done) })` (второй `close` паникует, `Once` от этого защищает), `Ready` — неблокирующее чтение: `select { case <-s.done: return true; default: return false }`. Закрытие synchronized before получения, увидевшего закрытие, поэтому горутина, дождавшаяся `Done`, увидит и `Ready() == true`.
