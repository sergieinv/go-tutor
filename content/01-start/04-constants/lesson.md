`const` объявляет значение, известное на этапе компиляции: число, строку, `bool` или руну. Константных массивов, срезов, структур и map нет — только базовые типы.

Главная особенность Go — **нетипизированные константы**. `const KiB = 1024` не имеет типа `int`: это «просто число», которое получает тип только там, где используется. Поэтому одну константу можно подставить и в `int64`, и в `float64`, и в `uint8` без преобразований. Пока константа не стала значением конкретного типа, компилятор считает её с произвольной точностью: `1 << 100` — допустимая константа, хотя ни в один целый тип она не помещается.

Для перечислений есть счётчик `iota` — его разберём в уроке 03-types/05-enums-iota.

## Как это в C#

- `const` в C# всегда типизирован: `const int KiB = 1024;`. Нетипизированная константа Go ближе к литералу, который подставляется в место использования и подстраивается под его тип.
- C# считает константные выражения в типе операндов: `1 << 40` для `int` — сдвиг по модулю 32, а `int.MaxValue + 1` — ошибка компиляции. Go считает точно и проверяет переполнение только при превращении в конкретный тип.
- `static readonly` для «констант» сложных типов в Go заменяют переменные уровня пакета: `var defaultNames = []string{...}`. Защиты от изменения у них нет.
- Как и в C#, константа может быть типизированной: `const Timeout int64 = 30`. Такая константа уже не подставится в `float64` без преобразования.

## Ловушки

### Точная арифметика констант и неточная — переменных

```go
const a, b = 0.1, 0.2
fmt.Println(a+b == 0.3) // true: считается точно на этапе компиляции
x, y := 0.1, 0.2
fmt.Println(x+y == 0.3) // false: float64 во время выполнения
```

Один и тот же код ведёт себя по-разному в зависимости от того, константы в нём или переменные.

### Деление нетипизированных целых остаётся целым

```go
var f float64 = 7 / 2
fmt.Println(f) // 3, а не 3.5
```

`7` и `2` — нетипизированные **целые** константы, поэтому `7 / 2` считается как целое деление и только потом превращается в `float64`. Нужно `7.0 / 2` или `7 / 2.0`.

### Константа переполняется в момент использования

```go
const big = 1 << 100
fmt.Println(big >> 98) // 4: всё ещё константа
fmt.Println(big)       // ошибка: overflows int
```

Пока выражение константное, точность не ограничена. Ошибка возникает, когда константу нужно превратить в значение конкретного типа — здесь в `int` для передачи в `Println`.

## Задание

Напишите функцию `HumanSize(n int64) string`, которая форматирует размер в байтах в двоичных единицах. Объявите константы `KiB`, `MiB`, `GiB`, `TiB` (1024, 1024², 1024³, 1024⁴) константными выражениями.

Требования:

- если `|n| < 1024`, результат — целое число и `B`: `"0 B"`, `"1023 B"`;
- иначе выбирается **наибольшая** единица из `KiB`, `MiB`, `GiB`, `TiB`, не превосходящая `|n|`, и значение печатается с одним знаком после запятой через `%.1f`: `1536` → `"1.5 KiB"`, `1048576` → `"1.0 MiB"`;
- единицы больше `TiB` нет: `5 * 1024⁵` → `"5120.0 TiB"`;
- отрицательный размер форматируется так же, со знаком минус: `-1536` → `"-1.5 KiB"`, `-5` → `"-5 B"`; это касается и `math.MinInt64` → `"-8388608.0 TiB"` (учтите, что `-n` для него переполняется и остаётся отрицательным).
