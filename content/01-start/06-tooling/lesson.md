Весь инструментарий Go — одна программа `go`. Отдельных систем сборки, форматтеров и тест-раннеров ставить не нужно:

```sh
go run .            # собрать во временный каталог и запустить пакет из текущего каталога
go build -o app ./cmd/app   # собрать бинарник
GOOS=linux GOARCH=arm64 go build ./cmd/app   # кросс-компиляция — две переменные окружения
go test ./...       # все тесты модуля; ./... — «этот каталог и все вложенные»
go vet ./...        # статический анализ: ошибки, которые компилятор пропускает
gofmt -l -w .       # отформатировать все файлы
go mod tidy         # привести go.mod и go.sum в порядок
go doc fmt.Printf   # документация из исходников
```

`gofmt` не настраивается: у него нет опций стиля, поэтому весь Go-код в мире выглядит одинаково — табы для отступов, выравнивание полей, скобки на своих местах. Споров о стиле нет, а дифы в ревью содержат только смысловые изменения. Редакторы запускают его при сохранении — обычно в виде `goimports`, который ещё и правит импорты.

`go vet` ищет код, который компилируется, но почти наверняка ошибочен: `Printf` с вербом не того типа или с неверным числом аргументов, `Println` с `%d` внутри, `x = x`, недостижимый код, копирование `sync.Mutex` по значению, неверные теги структур. Часть этих проверок, включая `printf`, `go test` запускает сам — и при находке тест даже не начнётся.

Типичная раскладка проекта:

```
shop/
  go.mod
  cmd/
    shop/main.go         # бинарник shop: go build ./cmd/shop
    shopctl/main.go      # второй бинарник
  internal/
    order/order.go       # бизнес-логика, недоступная другим модулям
    order/order_test.go  # тесты лежат рядом с кодом
  api/                   # контракты, схемы — по необходимости
```

Каталоги `cmd/` и `internal/` — общепринятое соглашение (а `internal/` — ещё и правило компилятора). Обязательного `src/` нет, а маленькому проекту хватит одного пакета в корне модуля.

## Как это в C#

- `dotnet build`/`run`/`test` — это `go build`/`run`/`test`. Но решения и проектных файлов нет: единица сборки — пакет, а зависимости между пакетами компилятор берёт из импортов.
- `.editorconfig` и `dotnet format` настраиваются, `gofmt` — нет. Стиль один на всех, и его соблюдение — норма сообщества, а не договорённость команды.
- Roslyn-анализаторы и предупреждения компилятора — это `go vet` (и сторонние `staticcheck`, `golangci-lint`). Сам компилятор Go предупреждений не выдаёт: либо ошибка, либо ничего.
- Тестовый фреймворк встроен: файлы `*_test.go`, функции `TestXxx(t *testing.T)`. Отдельного тестового проекта нет — тесты лежат рядом с кодом в том же пакете.

## Ловушки

### `go run main.go` видит только один файл

```sh
$ ls
go.mod  helper.go  main.go
$ go run main.go
./main.go:3:26: undefined: helper
$ go run .
ok
```

Список файлов — это не пакет: `go run main.go` компилирует ровно `main.go`. Чтобы собрать весь пакет из каталога, передавайте путь пакета — `go run .`.

### Ошибка формата — не ошибка компиляции

```go
fmt.Printf("%d items\n", "five") // %!d(string=five) items
fmt.Printf("%s and %s\n", "a")   // a and %!s(MISSING)
fmt.Println("total: %d", 5)      // total: %d 5
```

Компилятор проверяет только типы аргументов `...any`, а форматная строка для него — просто строка. Программа отработает и напечатает мусор. Ловит это `go vet`: `fmt.Printf format %d has arg "five" of wrong type string`.

### `go test` не стартует из-за vet

Если в пакете есть `Printf` с ошибкой формата, `go test` остановится ещё на сборке:

```
./report.go:12:13: fmt.Sprintf format %d has arg name of wrong type string
FAIL	example.com/shop [build failed]
```

Это не баг теста — исправьте вызов. Отключать проверку флагом `-vet=off` стоит только осознанно.

## Задание

Напишите упрощённую проверку `printf` из `go vet`.

`CountVerbs(format string) int` возвращает, сколько аргументов потребляет форматная строка, или `-1`, если она некорректна. Правила:

- `%%` — литеральный знак процента, аргумент не потребляет. `%%` распознаётся, только если второй `%` идёт сразу за первым; иначе после `%` разбираются флаги и т.д., и второй `%` на месте верба — ошибка: `"%-%"` и `"%5%"` некорректны;
- директива — это `%`, затем любое количество флагов из `+`, `-`, `#`, ` ` (пробел), `0`, затем необязательная ширина (цифры), затем необязательная точность — `.` и цифры (цифр может и не быть: `%.f`), и в конце — **верб**, латинская буква `a`–`z` или `A`–`Z`. Директива потребляет один аргумент;
- если после `%` (и, возможно, флагов, ширины и точности) строка кончилась или стоит не буква — формат некорректен. Это касается и `*`, и `[`: эти возможности `fmt` мы не поддерживаем;
- остальные символы, включая не-ASCII, — обычный текст.

`CheckCall(format string, nargs int) string` проверяет вызов вида `Printf(format, <nargs аргументов>)`:

- `""`, если всё в порядке;
- `"bad format"`, если формат некорректен;
- `"format reads N args, but call has M"` (N — результат `CountVerbs`, M — `nargs`), если числа не совпадают.
