Основной стиль тестов в Go — табличный. Случаи описываются данными: срез анонимных структур с полями «имя, вход, ожидание», а проверка пишется один раз в цикле. Добавить случай — дописать строку в таблицу; прочитать тест — пробежать глазами таблицу.

Каждый случай запускают подтестом: `t.Run(name, func(t *testing.T) {...})`. У подтеста свой `t`, своё имя `TestSlug/пробелы_по_краям` (пробелы заменены на `_`) и свой результат в выводе. Провал одного случая не мешает остальным, а `t.Fatalf` внутри подтеста останавливает только его. Нужный случай запускают по имени: `go test -run 'TestSlug/пробелы_по_краям'` — шаблон делится по `/`, и каждая часть — регулярное выражение для своего уровня имени.

## Как это в C#

- **`[Theory]` + `[InlineData]`** — та же идея: параметры отдельно, проверка одна. Но в атрибут попадают только константы, а сложные данные уходят в `[MemberData]`/`TheoryData<>`. В Go таблица — обычный литерал среза: внутри могут быть структуры, срезы, функции, ошибки.
- **Имя случая.** xUnit строит имя из значений аргументов (`Slug(title: "Hello World", ...)`); в Go имя задаёте вы полем `name`, и оно должно объяснять, *что* проверяется, а не повторять вход.
- **Сравнение.** Вместо `Assert.Equal(expected, actual)` для коллекций — `slices.Equal`, `maps.Equal`, для вложенных структур — `reflect.DeepEqual`. Сообщение — ваше: `Slug("Go 1.25") = "go-1.25", want "go-1-25"`. Порядок «got, want» — соглашение Go (в xUnit наоборот: `expected, actual`).
- **Один случай.** `dotnet test --filter` фильтрует по имени метода и трейтам; `go test -run 'TestX/случай'` — по имени подтеста, которое вы сами задали.

## Ловушки

### Таблица в map — случайный порядок

```go
tests := map[string]struct{ in, want string }{
	"простой": {"Hello World", "hello-world"},
	"пусто":   {"", ""},
}
for name, tt := range tests { t.Run(name, ...) }
```

Так тоже пишут: ключи гарантированно уникальны (повтор константного ключа — ошибка компиляции). Но порядок обхода map случаен — подтесты запускаются каждый раз в новом порядке, и падение, зависящее от порядка, «плавает». Если порядок важен для чтения вывода или случаи связаны, держите таблицу в срезе.

### Одинаковые имена случаев

```go
{"пусто", "", ""},
{"пусто", "   ", ""}, // скопировали строку и забыли переименовать
```

Тест не упадёт: `go test` сделает имена уникальными — `TestSlug/пусто` и `TestSlug/пусто#01`. Но по сообщению о провале уже не понять, какая из строк таблицы сломалась, а `-run 'TestSlug/пусто$'` выберет только первую. Имена случаев должны различаться.

### `nil` против пустого среза

```go
var got []string             // nil: фильтр ничего не нашёл, append не вызывался
want := []string{}
reflect.DeepEqual(got, want) // false — тест красный
slices.Equal(got, want)      // true
```

`reflect.DeepEqual` различает `nil` и пустые срезы и map, а `slices.Equal`/`maps.Equal` сравнивают только элементы. Для срезов и map берите их. До Go 1.22 была ещё ловушка с `t.Parallel()` в подтестах: замыкание видело общую переменную цикла `tt`, и все параллельные случаи проверяли последнюю строку таблицы. С `go 1.22` в `go.mod` переменная своя на каждой итерации и копия `tt := tt` не нужна.

## Задание

Тренируем не код, а таблицу. Дана функция:

```go
// IsLeap сообщает, високосный ли год по григорианскому календарю:
// делится на 4, но не на 100, либо делится на 400.
func IsLeap(year int) bool
```

Напишите таблицу случаев и функцию, которая её прогоняет:

```go
type Case struct {
	Name string
	Year int
	Want bool
}

func LeapCases() []Case
func Check(f func(int) bool, cases []Case) []string
```

Требования:

- `LeapCases` возвращает таблицу, в которой есть хотя бы по одному году каждого вида: не делится на 4; делится на 4, но не на 100; делится на 100, но не на 400; делится на 400. Все годы положительные, `Want` — правильный ответ для года, `Name` непустые и попарно различны;
- `Check` прогоняет таблицу против реализации `f`: для каждого случая по порядку вызывает `f(c.Year)` ровно один раз и, если результат не равен `c.Want`, добавляет сообщение `fmt.Sprintf("%s: IsLeap(%d) = %t, want %t", c.Name, c.Year, got, c.Want)`. Если все случаи прошли (или таблица пустая), возвращает `nil`;
- тесты проверяют, что `Check(IsLeap, LeapCases())` возвращает `nil`, а для типичных ошибочных реализаций — например, «только деление на 4» или «забыто правило 400» — таблица находит хотя бы одно расхождение.
