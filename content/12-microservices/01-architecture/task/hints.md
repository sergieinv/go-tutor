## Подсказка 1

Порядок в `PlaceOrder`: проверка входа → нормализация позиций → `newID()` → `Reserve` → `Publish` → сохранение под мьютексом. Каждая ранняя ошибка возвращает `Order{}` и ничего не трогает дальше по цепочке. Нормализация — map `SKU → сумма`, затем срез из неё и `slices.SortFunc` по `SKU`.

## Подсказка 2

Ошибки оборачивайте через `%w`: `fmt.Errorf("reserve %s: %w", id, err)`. Если после неудачной публикации `Release` тоже упал, нужны обе причины — `errors.Join(errPublish, errRelease)`. Для компенсации возьмите `context.WithoutCancel(ctx)`: значения контекста сохраняются, а отмена и дедлайн — нет. Чтобы чужой код не мог менять сохранённый заказ, отдавайте и храните копию: `slices.Clone(o.Lines)`.

## Подсказка 3

`MemStock` — мьютекс, map остатков и map резервов `orderID → []Line`. `Reserve`: `ctx.Err()`, проверка `Qty`, сложить потребность по SKU, под мьютексом — если резерв по id уже есть, вернуть `nil`; иначе сначала проверить все SKU (`m.stock[sku] < n` → `fmt.Errorf("%s: %w", sku, ErrOutOfStock)`), и только потом списать и запомнить резерв. `Release` возвращает запомненное и делает `delete` — повторный вызов найдёт пустой срез и ничего не сделает.
