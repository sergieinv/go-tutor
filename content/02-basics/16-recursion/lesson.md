Рекурсия в Go устроена привычно: функция вызывает саму себя, нужен базовый случай. Отличия — в стеке. Стек горутины начинается с нескольких килобайт и растёт по мере надобности: рантайм выделяет стек вдвое больше и копирует туда кадры. Поэтому глубина в сотни тысяч вызовов, на которой .NET-поток с 1 МБ стека упал бы со `StackOverflowException`, для Go — обычное дело.

Предел всё же есть: 1 ГБ на 64-битных платформах (250 МБ на 32-битных). При его превышении программа падает с `fatal error: stack overflow`. Это не паника: `recover` её не перехватит, процесс завершается. Оптимизации хвостового вызова компилятор Go не гарантирует, так что бесконечная или очень глубокая рекурсия рано или поздно упрётся в лимит — для неограниченной глубины пишите цикл.

## Как это в C#

- Стек потока в .NET фиксирован (1 МБ по умолчанию в Windows), переполнение — `StackOverflowException`, который тоже нельзя перехватить. В Go стек растёт динамически до 1 ГБ, лимит меняется через `debug.SetMaxStack`.
- JIT .NET иногда превращает хвостовой вызов в переход, а F# помечает такие вызовы IL-префиксом `tail.` (компилятор C# его не генерирует). Компилятор Go хвостовые вызовы не оптимизирует.
- Локальная функция C# может вызывать себя сразу. Литерал функции в Go — нет: сначала объявите переменную `var f func(int) int`, потом присвойте ей замыкание, которое вызывает `f`.

## Ловушки

### Рекурсивный литерал функции

```go
fact := func(n int) int {
	if n == 0 {
		return 1
	}
	return n * fact(n-1) // ошибка: undefined: fact
}
```

В момент разбора тела `fact` ещё не объявлена. Решение — объявить заранее:

```go
var fact func(int) int
fact = func(n int) int { ... fact(n-1) ... }
```

### Экспоненциальная рекурсия

```go
func fib(n int) int {
	if n < 2 {
		return n
	}
	return fib(n-1) + fib(n-2) // fib(50) — миллиарды вызовов
}
```

Наивный Фибоначчи пересчитывает одни и те же значения. Кэшируйте (как `Memo` из урока о замыканиях) или считайте циклом.

### Переполнение стека не ловится

```go
func down(n int) int { return down(n+1) + 1 }
// runtime: goroutine stack exceeds 1000000000-byte limit
// fatal error: stack overflow
```

`defer` с `recover` здесь не поможет: это фатальная ошибка рантайма, а не паника. Глубину рекурсии на пользовательских данных (вложенный JSON, глубокое дерево) ограничивайте сами.

## Задание

Дано двоичное дерево:

```go
type Node struct {
	Val         int
	Left, Right *Node
}
```

Напишите функции:

- `Sum(n *Node) int` — сумма всех значений; для `nil`-дерева — 0.
- `Depth(n *Node) int` — число уровней: `nil` — 0, один узел — 1.
- `InOrder(n *Node) []int` — значения в порядке «левое поддерево, узел, правое поддерево». Для `nil`-дерева — пустой срез длины 0 (не `nil`).
