Строка в Go — неизменяемая последовательность **байтов**. Компилятор кладёт литералы в UTF-8, и почти вся стандартная библиотека считает, что в строке UTF-8, но сам тип этого не гарантирует: в строке может лежать любой набор байтов. В C# `string` — последовательность UTF-16 `char`, и `s.Length` считает кодовые единицы UTF-16. В Go `len(s)` считает байты.

Символ Unicode в Go называется **руной**: `rune` — это псевдоним `int32`, кодовая точка. Индексация `s[i]` даёт байт (`byte` = `uint8`), а `for range` декодирует UTF-8 и отдаёт руны вместе с байтовым смещением.

## Как это в C#

- `string` в C# — UTF-16, `"мир".Length == 3`. В Go `len("мир") == 6`: каждая кириллическая буква занимает 2 байта UTF-8. Количество символов — `utf8.RuneCountInString`.
- `s[i]` в C# — `char` (кодовая единица UTF-16). В Go — `byte`; для символов нужен `range` или `[]rune(s)`.
- `char` в C# — 16 бит и не вмещает эмодзи (нужна суррогатная пара). `rune` в Go — 32 бита и вмещает любую кодовую точку.
- Обе строки неизменяемы. Но в Go `[]byte(s)` и `string(b)` копируют данные — аналог `Encoding.UTF8.GetBytes` и `GetString`, а не «просмотр» без копии.

## Под капотом

Строка — это заголовок из двух полей: указатель на байты и длина, `struct { ptr *byte; len int }`. Ёмкости нет — строку нельзя дорастить. Присваивание и передача в функцию копируют только заголовок, а байты общие: это безопасно, потому что их никто не может изменить. По той же причине `s[i:j]` не копирует данные. А вот `[]byte(s)` обязан скопировать: иначе через срез можно было бы поменять «неизменяемую» строку. Конкатенация тоже создаёт новый массив байтов.

## Ловушки

### Индекс — это байт, а не символ

```go
s := "мир"
fmt.Println(s[0])         // 208 — первый байт буквы «м»
fmt.Println(string(s[0])) // "Ð" — байт 208 как руна U+00D0
```

Нужны символы — используйте `for _, r := range s` или `[]rune(s)`.

### Срез строки может разрезать символ

```go
s := "мир"
fmt.Println(s[:1])               // "\xd0" — половина буквы
fmt.Println(utf8.ValidString(s[:1])) // false
```

Режьте по смещениям, которые вернул `range` или `strings.Index`, — они всегда на границе руны.

### `string(65)` — не "65"

```go
n := 65
fmt.Println(string(rune(n)))   // "A" — руна с кодом 65
fmt.Println(strconv.Itoa(n))   // "65"
```

Преобразование целого в строку даёт символ с этим кодом. `go vet` ругается на `string(n)` для `int`, а для числа в виде текста есть `strconv`.

## Задание

Напишите две функции:

- `Reverse(s string) string` — переворачивает строку по рунам: `Reverse("Go, мир")` == `"рим ,oG"`. Пустая строка остаётся пустой.
- `Truncate(s string, n int) string` — оставляет первые `n` рун строки. Если рун в строке не больше `n`, строка возвращается как есть. При `n <= 0` возвращается `""`. Результат никогда не разрезает многобайтовый символ.

Считайте, что вход — корректный UTF-8.
