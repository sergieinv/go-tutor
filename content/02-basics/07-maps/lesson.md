`map[K]V` — встроенная хеш-таблица, аналог `Dictionary<TKey, TValue>`. Ключом может быть любой сравнимый тип: числа, строки, указатели, массивы, структуры из сравнимых полей. Срез, map и функция ключом быть не могут.

Отличий от C# два. Чтение отсутствующего ключа не бросает исключение, а возвращает нулевое значение типа; проверить наличие ключа позволяет форма «comma ok»: `v, ok := m[k]`. Порядок обхода случаен — и это сделано специально. А вот что общего: переменная типа map, как и ссылка на `Dictionary`, — указатель на внутреннюю структуру, поэтому функция, получившая map, меняет ту же таблицу.

## Как это в C#

- `dict[k]` для отсутствующего ключа бросает `KeyNotFoundException`. `m[k]` в Go возвращает нулевое значение, а `v, ok := m[k]` — это `TryGetValue`.
- `Dictionary` перечисляется в порядке, который на практике часто совпадает с порядком вставки (но не гарантирован). В Go порядок `range` по map намеренно случаен. Нужен порядок — сортируйте ключи: `slices.Sorted(maps.Keys(m))`.
- `null`-словарь в C# падает на любом обращении. `nil`-map в Go можно читать, обходить и передавать в `len` — паникует только запись.
- `dict[k].Count++` для значения-структуры в C# — ошибка компиляции, и в Go тоже: элемент map не адресуем, `&m[k]` и `m[k].f = 1` не компилируются.

## Под капотом

С Go 1.24 map устроена как Swiss table. Элементы хранятся в **группах** по 8 слотов, у каждой группы есть 8-байтовое контрольное слово — по байту на слот. Хеш ключа делится на две части: младшие 7 бит (`h2`) записываются в контрольный байт занятого слота, а старшие 57 бит (`h1`) выбирают, с какой группы начинать поиск.

При поиске `h2` сравнивается со всеми восемью контрольными байтами одной побитовой операцией, и сами ключи сравниваются только в совпавших слотах. Пустой слот в группе означает, что искать дальше не нужно. Маленькая map (до 8 элементов) — это одна группа. Большая — таблица из групп, которая удваивается, когда заполнена на 7/8, а после 1024 слотов делится на две; таблицу выбирает каталог по старшим битам хеша. Поэтому рост никогда не перестраивает всю большую map разом.

Схема ниже упрощена: хеши условные, показана одна таблица из двух групп, а поиск в таблице на самом деле может пройти по цепочке групп (квадратичное пробирование), если в стартовой группе ключа нет, а пустых слотов тоже нет.

## Ловушки

### Запись в `nil`-map — паника

```go
var m map[string]int
fmt.Println(m["a"], len(m)) // 0 0 — читать можно
m["a"] = 1                  // panic: assignment to entry in nil map
```

Объявление `var m map[K]V` не создаёт таблицу. Создайте её через `make(map[K]V)` или литерал `map[K]V{}` — особенно в полях структур, которые не инициализируются сами.

### Нулевое значение не отличить от отсутствия ключа

```go
stock := map[string]int{"apple": 0}
if stock["apple"] == 0 && stock["pear"] == 0 {
	// оба условия истинны: нет на складе и нет в каталоге выглядят одинаково
}
if _, ok := stock["pear"]; !ok {
	fmt.Println("pear нет в каталоге")
}
```

Если ноль — допустимое значение, проверяйте наличие через comma ok.

### Нельзя изменить поле структуры прямо в map

```go
type user struct{ visits int }
users := map[string]user{"ann": {}}
users["ann"].visits++ // ошибка компиляции: cannot assign to struct field users["ann"].visits in map
u := users["ann"]
u.visits++
users["ann"] = u // правильно: прочитать копию, изменить, записать обратно
```

При росте таблицы элементы переезжают, поэтому адрес элемента map получить нельзя. Альтернатива — хранить указатели: `map[string]*user`.

## Задание

Напишите две функции.

`CountWords(text string) map[string]int` считает, сколько раз встречается каждое слово. Слова — это части текста, разделённые пробельными символами (`strings.Fields`), регистр не учитывается (`strings.ToLower`). Для текста без слов возвращается пустая, но не `nil` map — в неё можно сразу писать.

`MostFrequent(counts map[string]int) []string` возвращает слова с наибольшим счётчиком, отсортированные по алфавиту. Для пустой или `nil` map возвращается пустой срез (длины 0).
