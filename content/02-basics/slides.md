# Базовый синтаксис

Обзор модуля для показа команде: чем Go отличается от C# на уровне самых простых конструкций.

---

## Один цикл, zero values, без null

- `for` — единственный цикл: и `while`, и `foreach` через `range`.
- У каждой переменной есть нулевое значение: `0`, `""`, `false`, `nil`. Неинициализированных переменных нет.
- Неиспользуемая переменная или импорт — ошибка компиляции, а не предупреждение.
- С Go 1.22 у каждой итерации своя переменная цикла — замыкания больше не видят «последнее значение».

---

## `if` и `switch` без привычных подпорок

| C# | Go |
|---|---|
| `x = a > b ? a : b` | тернарного оператора нет: `x := max(a, b)` или `if` |
| `if (int.TryParse(s, out var n))` | `if n, err := strconv.Atoi(s); err != nil { … }` — `n` живёт только в `if` |
| `case 1: case 2:` подряд | `case 1, 2:` — пустой `case` ничего не делает |
| `break` в конце ветки | ветка завершается сама; провалиться — явный `fallthrough` |

`break` внутри `switch` выходит только из `switch` — для цикла нужна метка: `break loop`.

## Срез — не `List<T>`

Срез — маленькая структура из трёх полей: указатель на массив, `len` и `cap`. Присваивание копирует только эти три поля, массив остаётся общим.

```go
a := []int{1, 2, 3}
b := a      // тот же массив
b[0] = 100  // a[0] тоже 100
```

А массив `[3]int` — наоборот, значение: присваивание копирует все элементы, длина входит в тип.

## У среза нет методов

- `list.Contains`, `IndexOf`, `Sort` → `slices.Contains(s, x)`, `slices.Index`, `slices.Sort`.
- `slices.Delete` и `slices.Insert` возвращают новый заголовок — его присваивают, а старый срез считают испорченным:

```go
s := []int{1, 2, 3, 4, 5}
t := slices.Delete(s, 1, 3)
fmt.Println(t, s) // [1 4 5] [1 4 5 0 0]
```

`copy(dst, src)` копирует `min(len(dst), len(src))` элементов и ничего не выделяет.

## Map: нет ключа — нулевое значение

- `m[k]` для отсутствующего ключа не бросает исключение, а возвращает ноль; `v, ok := m[k]` — это `TryGetValue`.
- `nil`-map можно читать, а запись в неё — паника. Создают через `make` или `map[K]V{}`.
- Порядок `range` по map намеренно случаен. Внутри с Go 1.24 — Swiss table:

## Строка — байты UTF-8

- `len("мир") == 6`: считаются байты, а не символы. Символов — `utf8.RuneCountInString`.
- `s[i]` — байт, `for i, r := range s` — руна и её байтовое смещение.
- `rune` — 32 бита и вмещает любую кодовую точку, в отличие от `char`.

## Указатели вместо `ref` и классов

- Всё передаётся по значению, структура тоже. Разделяемость задают явно — указателем `*T`.
- Указатель — обычное значение: его кладут в поле, срез, map и возвращают из функции.
- Арифметики нет, память освобождает GC, разыменование `nil` — паника.

```go
func inc(p *int) { *p++ }

x := 1
inc(&x)        // x == 2
```

## Функции: несколько результатов вместо исключений и `out`

```go
n, err := strconv.Atoi(s) // вместо int.TryParse(s, out var n)
if err != nil {
	return 0, err         // ошибку возвращают наверх явно
}
v, ok := m[k]             // «запятая-ok» вместо TryGetValue
```

- Перегрузок, параметров по умолчанию и именованных аргументов нет.
- `params int[]` → `nums ...int`; `sum(s...)` передаёт **тот же** массив.

---

## Замыкания захватывают переменную

```go
x := 1
f := func() int { return x }
x = 2
fmt.Println(f()) // 2, а не 1
```

- Как лямбды C#: захвачена сама переменная, она переезжает в кучу.
- Функции сравниваются только с `nil` — «отписаться» через `-=` нельзя.
- Стек горутины растёт динамически до 1 ГБ; переполнение — `fatal error`, `recover` не поможет.

---

## Что запомнить

- Результат `append` всегда присваивают: `s = append(s, x)`.
- Независимую копию делает `slices.Clone` или `s[:len(s):len(s)]` перед `append`.
- Строка в Go — байты UTF-8, `len("ё")` равен 2.
- Запись в `nil`-map — паника, отсутствие ключа проверяют через `v, ok := m[k]`.
- `:=` во вложенном блоке создаёт новую переменную — следите за `err`.
