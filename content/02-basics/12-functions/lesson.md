Функция в Go объявляется словом `func`, тип пишется после имени — и у параметров, и у результата: `func add(a, b int) int`. Подряд идущие параметры одного типа можно перечислить через запятую и указать тип один раз. Функции живут на уровне пакета, а не внутри класса: вызывается `add(1, 2)` или `strings.ToUpper(s)`.

Функция — обычное значение: её можно положить в переменную, передать аргументом, вернуть из другой функции. Тип функции записывается как `func(int, int) int` — это аналог `Func<int, int, int>` в C#, только без зоопарка `Func`/`Action`/делегатов.

## Как это в C#

- Перегрузки нет: две функции с одним именем в пакете — ошибка компиляции. Вместо `Parse(string)` и `Parse(string, int)` пишут разные имена: `Parse`, `ParseBase`.
- Параметров по умолчанию и именованных аргументов нет. Варианты — несколько функций, структура с опциями или variadic-«функциональные опции».
- Тип функции `func(int) string` вместо `Func<int, string>` и `delegate`. Нулевое значение такой переменной — `nil`, вызов `nil`-функции — паника.
- У функции может быть несколько результатов, и результаты можно назвать — об этом следующий урок.

## Ловушки

### Неиспользуемый результат молча отбрасывается

```go
strings.ToUpper(s) // компилируется, но результат потерян — s не изменилась
s = strings.ToUpper(s)
```

Строки неизменяемы, и функции `strings` всегда возвращают новую строку. `go vet` такое не ловит, линтеры — иногда.

### Функции сравниваются только с `nil`

```go
f := strings.ToUpper
g := strings.ToUpper
fmt.Println(f == nil) // false
fmt.Println(f == g)   // ошибка компиляции: func can only be compared to nil
```

Поэтому функции не бывают ключами map и не ищутся в срезе через `slices.Contains`.

## Задание

Напишите две функции высшего порядка.

- `Map(nums []int, f func(int) int) []int` — возвращает **новый** срез из `f(x)` для каждого элемента; исходный срез не меняется. Для пустого или `nil` входа возвращает пустой срез длины 0 (не `nil`). Если `f == nil`, возвращает копию `nums` без изменений; для пустого или `nil` входа и тут действует правило выше — пустой срез длины 0 (не `nil`).
- `Reduce(nums []int, init int, f func(acc, x int) int) int` — сворачивает срез слева направо: `acc` начинается с `init`, для каждого элемента `acc = f(acc, x)`. Для пустого среза возвращает `init`. Если `f == nil`, тоже возвращает `init`.
