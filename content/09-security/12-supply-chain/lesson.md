Код зависимостей исполняется с теми же правами, что и ваш, поэтому цепочка поставки — такая же граница доверия, как HTTP-запрос. Угроз две. Первая — **подмена**: в сборку попадает не тот код, что опубликовал автор (взломанный прокси или зеркало, переписанный тег в репозитории, опечатка в имени модуля). Вторая — **известная уязвимость** в честном коде, который вы давно не обновляли.

От подмены Go защищает по умолчанию. `go.mod` фиксирует точные версии, а алгоритм выбора версий (MVS) берёт минимальную версию, удовлетворяющую всем `require`, — «плавающих» версий и неожиданных обновлений нет, отдельный lock-файл не нужен. `go.sum` хранит криптографические хеши каждой версии: всех файлов модуля (строка `h1:`) и отдельно его `go.mod` (строка `/go.mod h1:`). Модули скачиваются через прокси (`GOPROXY`, по умолчанию `https://proxy.golang.org,direct`), а хеш при первой загрузке сверяется с публичной базой контрольных сумм `sum.golang.org` (`GOSUMDB`) — журналом прозрачности, в котором у версии может быть только один хеш навсегда. Переписанный тег даст другой хеш, и `go` откажется собирать. С Go 1.16 команды сборки не меняют `go.mod` сами (`-mod=readonly` по умолчанию); в CI полезно проверить, что файлы в репозитории полны: `go mod tidy -diff` (Go 1.23) и `go mod verify` — модули в локальном кеше не изменены после скачивания.

Приватные модули не должны утекать в публичный прокси и базу сумм: `GOPRIVATE=git.corp.example/*` выключает для них и то и другое (это значение по умолчанию для `GONOPROXY` и `GONOSUMDB`). Директива `toolchain go1.25.4` в `go.mod` задаёт версию тулчейна: если локальный `go` старше, он скачает нужный — тоже через прокси и с проверкой суммы.

От известных уязвимостей — `govulncheck`. Он сверяет версии модулей с базой `vuln.go.dev`, но главное — строит граф вызовов вашего кода и сообщает уязвимость в разделе символов (`Symbol Results`), только если код **вызывает** уязвимую функцию. Уязвимости в модулях и пакетах, которые вы подключили, но уязвимых функций не вызываете, он по умолчанию лишь подсчитывает в итоговой строке (подробно — с `-show verbose`, разделы `Package Results` и `Module Results`). Так «в проекте 40 CVE» превращается в «2 из них достижимы — вот трассы». Ещё одна защита — минимализм: стандартная библиотека Go закрывает HTTP, JSON, криптографию и SQL, и каждый модуль сверх неё — чужой код, который надо обновлять и проверять.

В песочнице кнопка «govulncheck» проверяет модуль примера по снимку базы, встроенному в образ; дата снимка показана под результатом. Найдите `GO-2022-1059` и трассу к вызову `ParseAcceptLanguage`, затем поменяйте в `go.mod` версию на `v0.3.8` и запустите снова: уязвимость из раздела символов пропадёт. Итоговая строка про уязвимости в подключённых модулях может остаться: это зависит от даты снимка — в базе есть и более поздние уязвимости `x/text`, которые пример не вызывает.

## Как это в C#

- `PackageReference Version="1.2.*"` и диапазоны версий в NuGet — плавающие; воспроизводимость даёт `packages.lock.json` с `RestoreLockedMode`. В Go версии в `go.mod` точные всегда, а `go.sum` — не lock-файл, а список хешей: версии выбирает MVS по `go.mod`.
- Подписи пакетов NuGet и `trustedSigners` ≈ `go.sum` + `sum.golang.org`: в Go проверяется не подпись автора, а то, что все видят одинаковое содержимое версии.
- NuGet Audit при `dotnet restore` и `dotnet list package --vulnerable` работают на уровне пакета: «версия уязвима». `govulncheck` идёт глубже — до функции и трассы вызова, поэтому шума меньше.
- Package Source Mapping и приватный фид ≈ `GOPRIVATE`/`GONOPROXY` и корпоративный `GOPROXY`.

## Ловушки

### Версии сравнивают как строки

```go
// УЯЗВИМО: "v0.10.0" < "v0.9.0" как строки — уязвимая v0.9.5
// считается «новее» исправления v0.10.0.
if version < vuln.Fixed { report(vuln) }
```

Версии модулей — semver: числа сравниваются как числа, `v1.4.0-rc.1` меньше `v1.4.0`, а псевдоверсия `v0.3.8-0.20220101000000-abcdef123456` — это коммит **до** `v0.3.8`. В настоящем коде используйте `golang.org/x/mod/semver.Compare`, в задаче — свою реализацию.

### `replace` выключает проверку

```go
// go.mod
replace golang.org/x/crypto => github.com/someone/crypto v0.55.0
replace example.com/lib => ../lib
```

`replace` подменяет модуль целиком: код приходит из другого репозитория или с диска, а импорты в исходниках не меняются, и ревьюер их не заметит. Для локального пути хеш в `go.sum` не пишется вовсе. Директивы `replace` действуют только в главном модуле — в чужих зависимостях они игнорируются, — поэтому их держат на ревью `go.mod` и проверяют в CI.

### govulncheck молчит — не значит «уязвимостей нет»

```sh
govulncheck ./...         # исходники: вызовы видны
govulncheck -mode binary app  # бинарник: символы, без трасс
```

Анализ видит только то, что попало в граф вызовов: вызов через рефлексию или `plugin` он пропустит, а код под другими тегами сборки и `GOOS` не проверит, пока вы не запустите его с ними. База тоже не мгновенна: уязвимость появляется в ней после публикации. Запускайте `govulncheck` в CI регулярно, а не только при изменении зависимостей, и не игнорируйте уязвимости модулей без вызовов — сегодня функция не вызывается, завтра её вызовет новый код.

## Задание

Напишите проверку `go.mod` по локальной базе уязвимостей и списку разрешённых `replace` — то, что можно запускать в CI без сети.

```go
type Vuln struct {
	ID         string // "GO-2022-1059"
	Module     string // "golang.org/x/text"
	Introduced string // "" — уязвимы версии с самой первой
	Fixed      string // "" — исправления нет
}

func CompareVersions(a, b string) int
func Audit(gomod string, db []Vuln, allowReplace []string) ([]string, error)
```

**`CompareVersions(a, b)`** возвращает `-1`, `0` или `+1` по правилам semver 2.0.0. Версии всегда корректны: `vMAJOR.MINOR.PATCH`, затем необязательный `-пререлиз` (идентификаторы через точку) и необязательные метаданные `+сборка`.

- `MAJOR`, `MINOR`, `PATCH` сравниваются как числа.
- Версия без пререлиза больше версии с пререлизом при равных числах: `v1.4.0-rc.1 < v1.4.0`.
- Пререлизы сравниваются по идентификаторам слева направо: числовые (только цифры) — как числа, числовой меньше буквенно-цифрового, буквенно-цифровые — побайтово как строки; если все идентификаторы одного списка совпали с началом другого, меньше более короткий.
- Метаданные `+...` в сравнении не участвуют: `v2.0.0+incompatible == v2.0.0`.

Псевдоверсии (`v0.0.0-20220101000000-abcdef123456`, `v0.3.8-0.20220101000000-abcdef123456`) — обычные версии с пререлизом и сравниваются по тем же правилам.

**`Audit(gomod, db, allowReplace)`** разбирает текст `go.mod`:

- комментарий — от `//` до конца строки; пустые строки пропускаются; слова разделены пробельными символами;
- `require путь версия` — отдельной строкой или внутри блока `require (` … `)`, где каждая строка — `путь версия`;
- `replace старый [версия] => новый [версия]` — так же, строкой или блоком; `=>` — отдельное слово;
- остальные директивы (`module`, `go`, `toolchain`, `exclude`, `retract` и любые другие, строкой или блоком) пропускаются без проверки.

Находки — строки:

- `"<ID> <путь>@<версия>"` — для каждой пары «`require` × запись базы», где `Module` совпадает с путём и версия лежит в `[Introduced, Fixed)`: не меньше `Introduced` (если он не пуст) и меньше `Fixed` (если он не пуст);
- `"replace <старый путь>"` — для каждой директивы `replace`, у которой старый путь не входит в `allowReplace` (точное совпадение).

Результат отсортирован (`slices.Sort`), без повторов; если находок нет — пустой срез или `nil`. Ошибка (результат при этом не важен) — если в `require` не ровно два слова, если в `replace` нет `=>` или слов до или после него не одно-два, если блок не закрыт строкой `)` до конца файла.
