В модуле 8 валидация была про удобство: собрать ошибки полей и ответить `422`. Здесь тот же код читаем глазами атакующего. Граница доверия — место, где в программу входят данные, которых вы не контролируете: тело и заголовки запроса, параметры URL, ответы чужих API, файлы пользователей. Всё, что пересекло её, проверяется **сразу**, в три слоя по порядку: *размер* (сколько вообще читать), *форма* (что это за документ) и *значения* (диапазоны, длины, допустимые символы). Дальше по коду идут уже проверенные типизированные значения, а не «строка, которую где-то потом посмотрят».

**Размер — до разбора.** В Go нет лимита тела по умолчанию: без `http.MaxBytesReader(w, r.Body, n)` клиент пришлёт гигабайт, и `io.ReadAll` его прочитает. Вне HTTP то же делает `io.LimitReader(r, n+1)` — лишний байт отличает «ровно `n`» от «больше». Но лимит тела защищает только парсер: в мегабайт JSON помещается полмиллиона элементов массива, и если каждый станет запросом к базе — это DoS. Поэтому ограничивают и число элементов массивов, и длины строк. Глубину вложенности `encoding/json` ограничивает сам (10 000 уровней, ошибка `exceeded max depth`); свои рекурсивные структуры — деревья комментариев, вложенные фильтры — ограничивайте явно.

**Форма — строгий JSON.** `DisallowUnknownFields()` отвергает поля, которых нет в контракте: `"total_cents": 1` или `"role": "admin"` не должны пройти молча. `Decoder.Decode` читает одно значение и на хвост не смотрит — после него проверьте, что `dec.Token()` вернул `io.EOF`. А два свойства `encoding/json` поменять нельзя: **ключи сопоставляются без учёта регистра** (`"AMOUNT"` попадёт в поле с тегом `amount`), и **повтор ключа — не ошибка**, побеждает последнее значение. Само по себе это не дыра, но если перед сервисом стоит прокси, WAF или сервис на другом языке, который читает *первый* ключ или учитывает регистр, они проверят одно значение, а Go использует другое. Защита — проверять значения после разбора, по тому, что реально оказалось в структуре, и не полагаться на чужие проверки.

**Значения — целые числа.** Арифметика целых в Go не паникует и не бросает исключений: `qty * price` при переполнении заворачивается по модулю 2⁶⁴ и может стать отрицательным или маленьким положительным числом. Преобразование `int32(x)` молча отбрасывает старшие биты. Поэтому диапазоны проверяют **до** арифметики и преобразований, а строки разбирают сразу в нужную битность: `strconv.ParseInt(s, 10, 32)` вернёт `strconv.ErrRange`, а `strconv.Atoi` даст `int` (64 бита), который потом опасно сужать.

**Значения — строки.** `len(s)` — байты UTF-8, а лимит «100 символов» для людей — `utf8.RuneCountInString`. Колонка `VARCHAR(100)` в одних СУБД — байты, в других — символы, и проверка должна соответствовать хранилищу. Нормализация Unicode (NFC) для лимитов не нужна, но помните: «символ» на экране может состоять из нескольких рун (`é` как `e` + комбинирующий акцент, эмодзи с модификаторами), так что лимит в рунах — технический, а не визуальный. `encoding/json` заменяет невалидный UTF-8 на `U+FFFD`, но в заголовках, query и именах файлов он может прийти как есть — проверяйте `utf8.ValidString`.

## Как это в C#

- Kestrel по умолчанию ограничивает тело 30 МБ, а `[RequestSizeLimit]` меняет лимит для action. В Go лимита нет — `MaxBytesReader` в каждом хендлере или в общей middleware.
- `JsonSerializerOptions.Strict` (.NET 10) запрещает неизвестные поля и дубли ключей и учитывает регистр; хвост после объекта `System.Text.Json` отвергает по умолчанию. В Go неизвестные поля и хвост — `DisallowUnknownFields` и `dec.Token()`, а дубли и регистр не настраиваются: только проверка значений после разбора. Учтите, что ASP.NET (`JsonSerializerOptions.Web`) тоже сравнивает имена без учёта регистра.
- `checked { qty * price }` бросает `OverflowException`. В Go `checked` нет — только явные границы до умножения или проверка через деление.
- `(int)someLong` усекает молча, как `int32(x)`; `int.Parse` бросает исключение на переполнении, как `ParseInt(s, 10, 32)` возвращает `ErrRange`. `string.Length` считает UTF-16, `len` — байты UTF-8.

## Ловушки

### Лимит после чтения

```go
// УЯЗВИМО: гигабайт уже в памяти, проверка опоздала.
body, _ := io.ReadAll(r.Body)
if len(body) > 1<<20 {
	http.Error(w, "too large", http.StatusRequestEntityTooLarge)
	return
}
```

Лимит ставится на источник, а не на результат: `r.Body = http.MaxBytesReader(w, r.Body, 1<<20)` до любого чтения. Тогда чтение остановится на лимите с ошибкой `*http.MaxBytesError`.

### Частично заполненная структура

```go
var t Transfer
err := dec.Decode(&t) // {"to":"bob","amount":500,"fee":0} с DisallowUnknownFields
fmt.Println(t.To, t.Amount, err != nil) // bob 500 true
```

При ошибке декодер не откатывает уже заполненные поля. Если код «на всякий случай» продолжит работу с `t` после ошибки (например, запишет в аудит или вернёт в ответе), он использует непроверенные данные. После ошибки разбора структуру не трогайте — возвращайте нулевое значение.

### Обрезка строки по байтам

```go
name := "Анна Каренина"
short := name[:7] // "Анн\xd0" — половина руны «а»
fmt.Println(utf8.ValidString(short)) // false
```

`s[:n]` режет по байтам и может разрезать руну, а невалидный UTF-8 потом ломает JSON-ответ, базу или логи. Если строку нужно укоротить, отвергайте длинный ввод целиком или режьте по границе руны: `for i := range s` даёт байтовые смещения начала рун.

## Задание

Напишите разбор тела запроса «оформить заказ»:

```go
const MaxBody = 16 << 10

type Item struct {
	SKU        string `json:"sku"`
	Qty        int64  `json:"qty"`
	PriceCents int64  `json:"price_cents"`
}

type Order struct {
	Customer string `json:"customer"`
	Note     string `json:"note"`
	Items    []Item `json:"items"`
}

var (
	ErrTooLarge = errors.New("body too large")
	ErrInvalid  = errors.New("invalid order")
)

func ParseOrder(r io.Reader) (Order, int64, error)
```

`ParseOrder` читает тело из `r`, проверяет его и возвращает заказ как есть (без нормализации) и сумму `Σ qty × price_cents` в копейках. Проверки по порядку, первая неудача определяет ошибку:

1. **Размер.** Из `r` читается не больше `MaxBody + 1` байт, даже если поток бесконечен. Тело длиннее `MaxBody` байт — `ErrTooLarge`, независимо от содержимого. Ошибка чтения из `r` возвращается как есть или обёрнутой (`errors.Is` должен её находить).
2. **Форма.** Тело — ровно одно JSON-значение и только пробельные символы после него. Иначе — ошибка, для которой `errors.Is(err, ErrInvalid)`: синтаксическая ошибка, пустое тело, неизвестное поле (на верхнем уровне или в позиции), значение не того типа (в том числе дробное число или целое вне `int64`), любые данные после значения. Ключи сопоставляются с полями как в `encoding/json` — без учёта регистра; при повторе ключа действует последнее значение; отсутствующее поле или `null` — нулевое значение поля.
3. **Значения** (тоже `ErrInvalid`):
   - `customer` — не пустой после `strings.TrimSpace` и не длиннее 100 символов (рун; длина считается по исходной строке, без обрезки пробелов);
   - `note` — не длиннее 500 символов (рун), может быть пустым;
   - `items` — от 1 до 50 позиций;
   - `sku` — от 1 до 32 байт, только `A`–`Z`, `0`–`9` и `-`;
   - `qty` — от 1 до 1000; `price_cents` — от 0 до 1 000 000 000.

При любой ошибке функция возвращает `Order{}` и `0`.
