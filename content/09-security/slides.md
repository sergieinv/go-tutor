# Безопасность

Обзор модуля для показа команде: те же классы уязвимостей, что в ASP.NET, но без защит конвейера «из коробки».

---

## Конвейера нет — защиты пишете вы

| ASP.NET | Go |
| --- | --- |
| `[Authorize]`, политики | проверка владельца в хендлере |
| антифорджери-токены | `http.CrossOriginProtection` (Go 1.25) |
| автоэкранирование Razor | `html/template` |
| лимит тела в Kestrel | `http.MaxBytesReader` |

Поэтому модуль начинается с модели угроз: что защищаем, где граница доверия, что может пойти не так (STRIDE).

---

## Граница доверия и ввод

- Размер — до разбора: без `MaxBytesReader` клиент пришлёт гигабайт, и `io.ReadAll` его прочитает.
- Строгий JSON: `DisallowUnknownFields()` и проверка хвоста через `dec.Token()` == `io.EOF`.
- `encoding/json` сопоставляет ключи без учёта регистра, а повтор ключа — не ошибка: побеждает последний.
- Broken access control (IDOR): `[Authorize]` проверяет «вошёл», а «это его документ» — всегда ваш код. Для чужого объекта безопаснее `404`.

## SQL: плейсхолдер — данные отдельно от текста

```go
// Склейка: кавычка во вводе меняет структуру запроса.
q := "SELECT id FROM users WHERE name = '" + name + "'"

// Плейсхолдер: текст и значение уходят драйверу раздельно.
rows, err := db.QueryContext(ctx,
	"SELECT id FROM users WHERE name = ?", name)
```

Имя колонки и `ASC`/`DESC` — структура, их берут из allowlist. `ORDER BY ?` — сортировка по константе.

## Команды и пути

- `exec.Command(name, args...)` запускает без оболочки: `;` и `$(…)` ничего не значат. Но `-delete` во вводе станет флагом — ставьте `--`.
- `filepath.Join("/srv/files", "../../etc/passwd")` — это `/etc/passwd`. Join не защищает.
- `filepath.IsLocal` проверяет строку, но не симлинк. Полная защита — `os.OpenRoot(dir)` (Go 1.24).

`html/template` разбирает разметку шаблона и дописывает в каждое `{{…}}` экранировщик своего контекста: текст, атрибут, URL, JavaScript. `javascript:`-ссылка превращается в `#ZgotmplZ`.

## CSRF, пароли, криптография

- `http.CrossOriginProtection` смотрит на `Sec-Fetch-Site`, без токенов и состояния. CORS — ослабление same-origin, а не защита.
- Пароли — bcrypt (учитывает только 72 байта) или argon2id. Токены — `crypto/rand`, например `rand.Text()`; в базе — SHA-256 токена.
- Шифрование — AES-GCM со случайным nonce; повтор nonce под одним ключом ломает и секретность, и теги.
- TLS к своему CA — `RootCAs`, а не `InsecureSkipVerify`.

---

## SSRF и DoS

- URL строкой не проверить: `0.0.0.0`, `[::ffff:127.0.0.1]`, любое имя, редирект, DNS rebinding.
- Надёжная точка — адрес сокета в `net.Dialer.ControlContext` плюс классификаторы `netip.Addr`.
- `http.Server` по умолчанию без таймаутов: ставьте `ReadHeaderTimeout` (Slowloris), `MaxBytesReader`, лимит распакованного размера, семафор с `503`.
- `regexp` на RE2 — время линейно от длины входа, ReDoS нет, но длину входа ограничивают всё равно.

## Секреты, ошибки, зависимости

- Тип `Secret` с `Format`, `LogValue` и `MarshalJSON`; значение — только через явный `Reveal()`.
- `slog` `ReplaceAttr` закрывает ключи вроде `password` и `authorization`.
- Клиенту — «internal error» и id запроса, полный текст — в лог.
- `go.sum` и `sum.golang.org` защищают от подмены; `govulncheck` говорит, вызывает ли ваш код уязвимую функцию.

---

## Что запомнить

- Каждая защита ASP.NET «по умолчанию» в Go — строка вашего кода; ревью — проход по чек-листу.
- Значения — плейсхолдером, идентификаторы — allowlist, пути — через `os.Root`.
- `html/template`, а не `text/template`; `template.HTML` из ввода — дыра.
- Лимиты и таймауты ставятся по слоям: соединение, тело, обработка.
