Команда и путь к файлу — две строки, которые программа отдаёт «наружу»: оболочке, чужой программе, файловой системе. Если в такую строку попал ввод пользователя, он может поменять её смысл. В Go ни одна из этих границ не защищена «по умолчанию целиком» — защита складывается из трёх правил.

**Без оболочки.** `exec.Command(name, args...)` запускает программу напрямую: каждый аргумент — отдельный элемент `argv`, `;`, `|`, `$(…)` и кавычки ничего не значат. Инъекция появляется, только когда вы сами зовёте `/bin/sh -c` и вклеиваете ввод в скрипт. Но и без оболочки остаётся **инъекция в аргументы**: значение `-delete` или `--upload-pack=…` вызываемая программа примет за флаг. Защита — `--` перед позиционными аргументами (почти все утилиты и пакет `flag` понимают его как «флаги кончились»), а где `--` не поддерживается — запрет ведущего `-` или префикс `./`.

**Путь не склеивать вслепую.** `filepath.Join(dir, name)` чистит результат и честно поднимается по `..`: `Join("/srv/files", "../../etc/passwd")` — это `/etc/passwd`. `filepath.IsLocal(name)` (Go 1.20) проверяет строку: не пустая, не абсолютная, не уходит вверх после очистки, в Windows — без зарезервированных имён вроде `NUL`. Но строкой не поймать **симлинк**: `avatar.png` внутри каталога может указывать на `/etc/shadow`. Полная защита — `os.Root` (Go 1.24): `os.OpenRoot(dir)` открывает дескриптор каталога, и все операции через него (`Open`, `Create`, `OpenFile`, `Stat`, `Mkdir`, `Remove`, а с Go 1.25 — `ReadFile`, `WriteFile`, `MkdirAll`, `RemoveAll`, `Rename` и другие) разрешают каждый элемент пути относительно этого дескриптора. Выход за пределы — через `..`, абсолютный путь или симлинк — даёт ошибку `path escapes from parent`; симлинки, ведущие внутрь, работают. Для разовых открытий есть `os.OpenInRoot(dir, name)`, для `http.FileServerFS` и `io/fs` — `root.FS()`.

**Имя из архива — тоже ввод.** Zip slip: запись `../../home/app/.ssh/authorized_keys` в загруженном архиве. `archive/zip` по умолчанию такие имена не отвергает (см. ловушки), и распаковка через `filepath.Join` пишет куда угодно. Проверяйте все имена до записи и пишите через `os.Root`; записи-симлинки из чужих архивов не создавайте. Размер распакованных данных — тоже граница доверия, о zip-бомбах — в уроке 10.

## Как это в C#

- `ProcessStartInfo.ArgumentList` ≈ аргументы `exec.Command`: каждый элемент доходит до программы как есть. Свойство `Arguments` — одна строка, которую разбирают по правилам командной строки, и кавычки во вводе меняют число аргументов. `cmd.exe /c` со строкой — то же, что `sh -c`.
- `Path.Combine`/`Path.Join` защищают от `..` не больше `filepath.Join`. Классическая проверка — `Path.GetFullPath` и `StartsWith(root + separator)`: она ловит `..`, но не симлинки. Аналога `os.Root`, работающего через дескриптор каталога, в .NET нет.
- `ZipFile.ExtractToDirectory` в .NET Core сам бросает `IOException` на записи вне целевого каталога. В Go распаковку пишете вы, и проверка — ваша.
- ASP.NET Core `PhysicalFileProvider` (и `UseStaticFiles`) отвергает `..` и абсолютные пути. Ближайший аналог в Go — `http.FileServerFS(root.FS())`: `http.Dir` тоже не пускает `..`, но симлинки наружу отдаёт.

## Ловушки

### Проверка префиксом строки

```go
// УЯЗВИМО: "/srv/files-old/secret" тоже начинается с "/srv/files",
// а симлинк внутри каталога проверку проходит.
p := filepath.Join(base, name)
if !strings.HasPrefix(p, base) {
	return errBadName
}
```

Префикс строки — не «внутри каталога»: нужен хотя бы `base + string(filepath.Separator)`, а симлинки так не поймать вообще. Проверяйте имя `filepath.IsLocal` и открывайте через `os.Root`.

### Сначала `EvalSymlinks`, потом открыть

```go
// УЯЗВИМО: между проверкой и открытием симлинк можно подменить (TOCTOU).
real, _ := filepath.EvalSymlinks(filepath.Join(dir, name))
if strings.HasPrefix(real, dir+"/") {
	data, _ = os.ReadFile(real)
}
```

Путь проверен в один момент, а открыт в другой. Если в каталог может писать кто-то ещё (загрузки, распаковка, общий том), он успеет заменить файл симлинком. `os.Root` проверяет каждый элемент в момент открытия — идёт по пути через `openat` относительно дескриптора и сам разбирает встреченные симлинки — и такой гонки не имеет.

### `zip.NewReader` не отвергает `../`

```go
zr, err := zip.NewReader(r, size) // err == nil, хотя в архиве "../evil.txt"
for _, f := range zr.File {
	// УЯЗВИМО: запись вне dst
	os.WriteFile(filepath.Join(dst, f.Name), data, 0o644)
}
```

С Go 1.20 есть настройка `GODEBUG=zipinsecurepath=0`: тогда `NewReader` возвращает `zip.ErrInsecurePath` для нелокальных имён (и всё равно отдаёт читатель). По умолчанию проверка выключена, а записи-симлинки она не проверяет вовсе. Проверяйте каждое `f.Name` сами и пишите через `os.Root`.

## Задание

Напишите хранилище файлов пользователей:

```go
var ErrBadName = errors.New("bad file name")

func NewStore(dir string) (*Store, error)
func (s *Store) Close() error
func (s *Store) Read(name string) ([]byte, error)
func (s *Store) Extract(zr *zip.Reader) error
func (s *Store) ThumbnailCmd(tool, name string) (*exec.Cmd, error)
```

`Read` и `Extract` не читают и не пишут за пределами каталога `dir` — ни через `..`, ни через абсолютный путь, ни через симлинк, который уже лежит в каталоге или пришёл в архиве. `ThumbnailCmd` файловую систему не трогает и проверяет только имя.

- `NewStore` открывает хранилище; если каталога нет — ошибка. `Close` освобождает ресурсы.
- **Допустимое имя** — то, для которого `filepath.IsLocal` возвращает `true`: не пустое, не абсолютное, после очистки не уходит выше `dir`. Имя, начинающееся с `-`, допустимо.
- `Read(name)` возвращает содержимое файла `dir/name`. Недопустимое имя — `nil` и ошибка с `errors.Is(err, ErrBadName)`. Нет файла — ошибка с `errors.Is(err, fs.ErrNotExist)`. Симлинк, который ведёт внутри `dir`, читается как обычный файл; если путь через симлинк выходит за пределы `dir` — `nil` и любая ошибка.
- `Extract(zr)` распаковывает архив в `dir`. Имя записи — путь со слешами; запись, оканчивающаяся на `/`, — каталог. Сначала проверяются **все** записи: если хоть одно имя (без завершающего `/`) недопустимо или запись — не обычный файл и не каталог (например, симлинк), возвращается ошибка с `ErrBadName` и ничего не пишется. Затем записи распаковываются по порядку: недостающие каталоги создаются (`0o755`), файлы создаются или перезаписываются (`0o644`). Если запись пришлось бы сделать за пределами `dir` через симлинк в каталоге — ошибка (уже записанные файлы остаются). Пустой архив — `nil`.
- `ThumbnailCmd(tool, name)` готовит, но не запускает, внешнюю утилиту миниатюр. Утилита понимает `tool [-size N] [-o выход] [вход]`: флаги разбирает пакетом `flag`, вход читает как путь относительно текущего каталога (без входа — читает stdin), результат пишет в `thumb_<имя входа>`. Команда запускает `tool` с флагом `-size 64` и файлом `name` как входом, текущий каталог процесса — `dir`, переменные окружения не меняются (`Env` не заполняйте). Для любого допустимого имени, включая `-dash.png` и `a; b.png`, утилита должна получить его именно как имя входного файла. Недопустимое имя — `nil` и ошибка с `ErrBadName`. Существование и тип файла `ThumbnailCmd` не проверяет (симлинки в `dir` — забота того, кто кладёт туда файлы).
