`http.ServeMux` — маршрутизатор из стандартной библиотеки, и сам он тоже `http.Handler`. До Go 1.22 он умел только префиксы путей, поэтому все брали `gorilla/mux` или `chi`. Теперь шаблон выглядит как `"[МЕТОД ][хост]/путь"`: `"GET /books/{id}"`, `"DELETE /books/{id}"`, `"api.example.com/"`. Параметр `{name}` совпадает ровно с одним сегментом пути, `{name...}` в конце шаблона — с остатком пути вместе со слешами. Значения достаёт `r.PathValue("name")` (уже раскодированными: `%2F` станет `/`), а сработавший шаблон лежит в `r.Pattern` (Go 1.23).

Шаблон, который кончается на `/`, описывает поддерево: `"/static/"` совпадёт с `/static/css/app.css`. Отсюда частая неожиданность: `"/"` совпадает со всеми путями. Чтобы совпал только сам путь со слешем, в конце пишут `{$}`: `"GET /{$}"` — только главная страница. Порядок регистрации не важен. Если запросу подходят несколько шаблонов, выигрывает **более специфичный** — тот, что совпадает со строгим подмножеством запросов другого: `/books/new` специфичнее `/books/{id}`, `GET /x` — специфичнее `/x`. Если ни один из двух шаблонов не специфичнее другого, а общие пути у них есть, это конфликт, и `Handle` паникует прямо при регистрации — ошибка видна при старте, а не на проде.

Остальное `ServeMux` делает сам. Нет подходящего шаблона — `404 page not found`. Путь подходит, а метод нет — `405 Method Not Allowed` с заголовком `Allow`, где перечислены допустимые методы. Шаблон с `GET` обслуживает и `HEAD`. Запрос `/files` при зарегистрированном поддереве `/files/` получает редирект на `/files/` (301 в Go 1.25, в новых версиях 307), а путь вида `/a//b/../c` — редирект на очищенный `/a/c`.

## Как это в C#

- Атрибутная маршрутизация `[HttpGet("books/{id}")]` и `app.MapGet("/books/{id}", ...)` ≈ `mux.HandleFunc("GET /books/{id}", ...)`. Но в Go параметр — всегда строка: `r.PathValue("id")` разбирайте и проверяйте сами (`strconv.Atoi`), а в .NET это делает model binding.
- Route constraints (`{id:int}`, `{slug:regex(...)}`) в `ServeMux` нет. Не прошедший проверку параметр — ваш `404` или `400` из хендлера. Catch-all `{**path}` ≈ `{path...}`.
- ASP.NET Core при неоднозначности бросает `AmbiguousMatchException` на запросе; `ServeMux` паникует при регистрации — конфликт виден сразу при запуске.
- 405 с `Allow` .NET-маршрутизация тоже возвращает сама — так что здесь различий меньше, чем кажется. Порядок маршрутов не важен ни там, ни там: побеждает более специфичный.

## Ловушки

### `"/"` ловит всё

```go
mux.HandleFunc("GET /", home)          // и /favicon.ico, и /wp-admin.php
mux.HandleFunc("GET /{$}", home)       // только /
```

Шаблон со слешем на конце — поддерево. Без `{$}` главная страница отвечает 200 на любой несуществующий путь, а вместо `404` пользователь видит главную.

### Конфликт шаблонов — паника

```go
mux.HandleFunc("GET /posts/{id}", getPost)
mux.HandleFunc("GET /{kind}/latest", latest) // panic: ... conflicts with pattern "GET /posts/{id}"
```

Оба совпадают с `/posts/latest`, но ни один не специфичнее другого. Паника при регистрации — это хорошо: напишите тест, который просто создаёт роутер, и конфликт не уедет в прод. Решение — сделать один шаблон специфичнее: добавить литеральный `GET /posts/latest`.

### `PathValue` не проверяет тип

```go
mux.HandleFunc("GET /books/{id}", func(w http.ResponseWriter, r *http.Request) {
	id, _ := strconv.Atoi(r.PathValue("id")) // /books/abc → id == 0
	...
})
```

Шаблон не знает, что `id` — число: `/books/abc` и `/books/-1` до хендлера дойдут. Проверяйте ошибку разбора и диапазон и отвечайте `404`. Имя параметра — тоже просто строка: опечатка `r.PathValue("ID")` вернёт `""` без ошибки.

## Задание

Напишите роутер небольшого API заметок:

```go
func NewRouter() http.Handler
```

Каждый вызов создаёт пустое хранилище в памяти. Используйте `http.ServeMux`: автоматические ответы `404`, `405` с `Allow` и редиректы должны быть его стандартными ответами. Маршруты (все ответы, кроме `204`, — текст):

| Запрос | Ответ |
| --- | --- |
| `GET /{$}` | `200`, тело `notes api\n` |
| `GET admin.local/{$}` (запрос с хостом `admin.local`) | `200`, тело `admin\n` |
| `GET /notes/{$}` | `200`, все заметки по возрастанию id, строка `<id>: <text>\n` на каждую; нет заметок — пустое тело |
| `POST /notes/{$}` | создать заметку из тела запроса (см. ниже): `201`, заголовок `Location: /notes/<id>`, тело `<id>\n` |
| `GET /notes/count` | `200`, тело — число заметок и `\n` |
| `GET /notes/{id}` | `200`, тело `<text>\n` |
| `DELETE /notes/{id}` | `204` без тела |
| `GET /raw/{path...}` | `200`, тело `raw: <path>\n`, где `<path>` — значение `PathValue` |

- id выдаются по порядку с 1 и не переиспользуются после удаления;
- `{id}` — положительное целое в десятичной записи без знака и ведущих нулей (`7`, но не `07`, `+7`, `-7`); если это не так или заметки с таким id нет — `http.NotFound(w, r)` (тело `404 page not found\n`), в том числе для `DELETE`;
- тело `POST` читается не больше 1024 байт (`http.MaxBytesReader`); длиннее — `http.Error(w, "too large", 413)`; текст заметки — тело без пробельных символов по краям (`strings.TrimSpace`), пустой текст — `http.Error(w, "empty note", 400)`;
- литерал `count` есть только у `GET`: `DELETE /notes/count` — это `DELETE /notes/{id}` с `id` = `count`, ответ `404`.
