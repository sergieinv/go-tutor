Интерфейс — набор методов. Тип реализует интерфейс, если у него есть все эти методы, — и всё: никакого `: IShape` в объявлении типа. Это структурная типизация на этапе компиляции: проверяется совпадение методов, а не явное объявление.

Отсюда другой стиль проектирования. Интерфейс объявляет не тот, кто реализует, а тот, кто использует: функции нужен «что-то, из чего можно читать» — она объявляет `interface{ Read([]byte) (int, error) }`, и ей подойдёт любой подходящий тип, даже написанный до появления этого интерфейса. Поэтому интерфейсы Go маленькие — часто из одного метода.

## Как это в C#

- В C# класс обязан перечислить интерфейсы: `class Rect : IShape`. В Go связь неявная — тип из чужой библиотеки можно использовать через ваш интерфейс без обёрток.
- В C# интерфейсы обычно объявляют рядом с реализацией и делают широкими (`IRepository` с десятком методов). В Go интерфейс объявляют у потребителя и держат минимальным: `io.Reader`, `fmt.Stringer`, `error` — по одному методу.
- `object` → `any`. `any` — просто псевдоним для `interface{}`, пустого интерфейса, которому удовлетворяет любой тип.
- Явной реализации интерфейса (`void IShape.Area()`) и default-методов в интерфейсах в Go нет.

## Ловушки

### Опечатка в сигнатуре — и тип молча не реализует интерфейс

```go
type Shape interface{ Area() float64 }
type Square struct{ side int }
func (s Square) Area() int { return s.side * s.side } // int, а не float64
```

Ошибка всплывёт только там, где `Square` впервые используют как `Shape`, — возможно, в другом пакете. Поставьте рядом с типом проверку: `var _ Shape = Square{}` (или `var _ Shape = (*Square)(nil)` для pointer-методов) — она ничего не стоит во время выполнения, но сломает сборку сразу.

### Интерфейс «на вырост»

```go
type UserService interface { Get(id int) User; Save(u User); Delete(id int); ... }
func NewUserService() UserService { return &userService{} }
```

Привычка из C# — спрятать реализацию за интерфейсом. В Go конструктор возвращает конкретный тип `*UserService`, а интерфейс из нужных ему методов объявляет потребитель, например тест с фейком. «Принимай интерфейсы, возвращай структуры».

### Интерфейс хранит копию значения

```go
s := Square{side: 2}
var sh Shape = s
s.side = 3
fmt.Println(sh.Area()) // 4: в интерфейс скопировано значение
```

## Задание

Есть интерфейс источника значений:

```go
type Getter interface {
	Get(key string) (string, bool)
}
```

Реализуйте:

- `type MapGetter map[string]string` — метод `Get` ищет ключ в map; `nil`-значение `MapGetter` ничего не находит и не паникует;
- `type Chain []Getter` — метод `Get` опрашивает источники по порядку и возвращает первое найденное значение. «Найдено» означает `ok == true`, даже если само значение — пустая строка `""`: на таком источнике цепочка останавливается; элементы-`nil` пропускаются; пустая цепочка ничего не находит. `Chain` сама является `Getter`, поэтому цепочки можно вкладывать друг в друга;
- `GetOr(g Getter, key, def string) string` — значение по ключу или `def`, если ключа нет (`ok == false`); найденное пустое значение `""` возвращается как есть.

Добавьте в решение проверки на этапе компиляции, что `MapGetter` и `Chain` реализуют `Getter`.
