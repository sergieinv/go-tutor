Переменная интерфейсного типа хранит два слова: динамический тип того, что в неё положили, и указатель на само значение. Статический тип переменной — `io.Writer` — не меняется, а пара (тип, значение) меняется при каждом присваивании.

Из этой пары следует всё остальное. Type assertion `v.(T)` проверяет первое слово и достаёт второе. Интерфейс равен `nil`, только если пусты оба слова, — поэтому интерфейс, в котором лежит nil-указатель, не равен `nil`. Это самая известная ловушка Go, и чаще всего на неё наступают с `error` (модуль 4).

## Как это в C#

- `obj is Dog d` → `d, ok := v.(Dog)`. Форма без `ok` — `v.(Dog)` — аналог приведения `(Dog)obj`: при несовпадении паника, как `InvalidCastException`.
- `switch (obj) { case Dog d: ... }` → `switch d := v.(type) { case Dog: ... }`. Ветки проверяются по порядку, ветка `case nil` ловит nil-интерфейс.
- В C# переменная `IWriter w = null` и «объект, в котором что-то null» различить просто: ссылка либо есть, либо нет. В Go интерфейс может быть «не nil», хотя указатель внутри — `nil`.
- Упаковка значимого типа в интерфейс похожа на boxing в C#: значение копируется, и изменения оригинала в интерфейс не попадают.

## Под капотом

В рантайме (`runtime/runtime2.go`) пустой интерфейс `any` — структура `eface{_type, data}`, непустой — `iface{tab, data}`. Поле `tab` указывает на `itab` (`internal/abi`, тип `ITab`): в нём интерфейс `Inter`, динамический тип `Type`, хэш типа для type switch и таблица методов `Fun`, через которую идёт вызов `w.Write(...)`. Указатели кладутся прямо в слово `data`, остальные значения — копируются, а `data` указывает на копию.

Визуализатор показывает, что лежит в этих двух словах при присваивании значения, указателя и nil-указателя, при сравнении с `nil` и при type assertion.

## Ловушки

### nil-указатель в интерфейсе — не nil

```go
func find() error {
	var err *NotFoundError // nil
	return err             // интерфейс (тип *NotFoundError, nil)
}
fmt.Println(find() == nil) // false
```

Возвращайте `nil` явно: `return nil`. Не храните результат в переменной конкретного типа, если функция возвращает интерфейс.

### Паника при assertion без `ok`

```go
var v any = "42"
n := v.(int) // panic: interface conversion: interface {} is string, not int
```

Если тип не гарантирован, используйте форму `n, ok := v.(int)` или type switch.

### Порядок веток в type switch

```go
switch v.(type) {
case fmt.Stringer: // сработает и для ошибки, у которой есть String()
case error:        // сюда такая ошибка уже не попадёт
}
```

Ветки проверяются сверху вниз, и интерфейсные ветки могут перекрываться. Ставьте более специфичные выше.

## Задание

Дан тип ошибки `FieldError` с методом `Error()` на указателе.

Напишите:

- `FirstError(errs ...*FieldError) error` — возвращает первый не-`nil` элемент как `error`. Если таких нет (в том числе для пустого списка), результат должен быть равен `nil` — то есть сравнение `FirstError(...) == nil` даёт `true`.
- `Kind(v any) string` — классифицирует значение с помощью type switch:
  - `"nil"` — если `v` — nil-интерфейс;
  - `"int"` — для `int`, `"string"` — для `string`;
  - `"error"` — если значение реализует `error` (даже если внутри nil-указатель);
  - `"stringer"` — если реализует `fmt.Stringer`, но не `error`;
  - `"other"` — во всех остальных случаях.
