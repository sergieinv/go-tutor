Наследования в Go нет. Вместо него — встраивание: поле структуры без имени, только с типом (`type Admin struct { User; Level int }`). Поля и методы встроенного значения «продвигаются» наверх: можно писать `a.Name` и `a.Greet()` вместо `a.User.Name` и `a.User.Greet()`. Вместе с методами продвигается и реализация интерфейсов.

Но это синтаксический сахар над обычным полем. `Admin` не является `User`, его нельзя передать туда, где ждут `User`, а методы `User` ничего не знают о внешней структуре. Если `Admin` объявит свой метод с тем же именем, он затенит метод `User` — но только для вызовов снаружи. Внутри `User` вызов `u.Role()` всегда вызовет `User.Role`: виртуальных методов нет.

## Как это в C#

- `class Admin : User` — наследование: `Admin` является `User`, и его можно передать в метод, принимающий `User`. Встраивание такого не даёт — подходит только интерфейс, который реализован продвинутыми методами.
- `override` в C# работает полиморфно: базовый класс, вызывая `this.Role()`, попадёт в метод наследника. В Go метод встроенного типа вызывает только свои методы.
- Ближе всего к встраиванию — композиция с делегированием в C#: поле `_user` и методы, пересылающие вызов ему. Go пишет такие пересылки за вас.
- Встраивание интерфейса в интерфейс (`type ReadWriter interface { Reader; Writer }`) — аналог `interface IReadWriter : IReader, IWriter`.

## Ловушки

### «Переопределение» не полиморфно

```go
func (b Base) Hello() string { return "I am " + b.Name() }
func (b Base) Name() string  { return "base" }
func (d Derived) Name() string { return "derived" } // Derived встраивает Base

fmt.Println(Derived{}.Hello()) // I am base
```

`Hello` — метод `Base`, и `b` в нём — значение типа `Base`. Если поведение должно настраиваться, передайте его явно: полем-функцией или интерфейсом.

### Встроенный nil-интерфейс паникует при вызове

```go
type LoggedStore struct{ Store } // Store — интерфейс
s := LoggedStore{}
s.Get("k") // panic: nil pointer dereference — поле Store не задано
```

Встраивание интерфейса удобно, чтобы переопределить один метод из многих, но остальные методы пересылаются в поле, а оно по умолчанию `nil`.

### Неоднозначные имена

Если два встроенных типа на одной глубине дают поле или метод с одинаковым именем, обращение к нему не скомпилируется (`ambiguous selector`). Обращайтесь явно: `x.A.Close()`.

## Задание

Дан интерфейс хранилища и его реализация на map:

```go
type Store interface {
	Get(key string) (string, bool)
	Set(key, value string) error
}
```

Сделайте две обёртки, которые встраивают `Store`:

- `CountingStore{ Store; Gets, Sets int }` — пересылает вызовы во встроенное хранилище и считает их: каждый вызов `Get` увеличивает `Gets`, каждый вызов `Set` — `Sets` (независимо от результата). Методы — на указателе `*CountingStore`;
- `ReadOnlyStore{ Store }` — `Get` пересылается во встроенное хранилище как есть (продвижением, без своего метода), а `Set` ничего не меняет и не вызывает встроенное хранилище, возвращая `ErrReadOnly`.

Обёртки должны комбинироваться: `ReadOnlyStore{&CountingStore{Store: m}}` — `Get` проходит сквозь оба слоя и считается, `Set` останавливается на `ReadOnlyStore` и не считается.
