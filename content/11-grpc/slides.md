# Контракты и gRPC

Обзор модуля для показа команде: контракт в `.proto` как источник истины, gRPC от unary до стримов и REST из того же контракта.

---

## Контракт — один на все языки

- Сообщения и сервисы описывают в `.proto`, код для Go и C# генерируют из него.
- По проводу идёт **номер** поля, а не имя. Номер нельзя менять, а удалённый — переиспользовать: его объявляют `reserved`.
- Сообщение protobuf передают указателем: внутри мьютекс, копию делают `proto.Clone`, сравнивают `proto.Equal`.
- Нулевое значение enum — то, что видит получатель, если поле не пришло. Поэтому `0` — это `..._UNSPECIFIED`, а не «новый».

---

## Эволюция без поломок

- Каждое изменение совместимо в обе стороны: новый код читает старые байты, старый — новые.
- Неизвестные поля получатель пропускает, отсутствующие становятся нулями.
- Переименование безопасно для бинарного формата, но ломает JSON.
- Несовместимое изменение — новый пакет: `orders.v1` → `orders.v2`.

## Unary: сервер и клиент

- Сервер — ваша структура со встроенным `UnimplementedOrderServiceServer` (по значению): новый метод контракта отвечает `Unimplemented`, а не ломает сборку.
- `grpc.NewServer` — свой HTTP/2-сервер, без Kestrel; опции задаются только при создании.
- `grpc.NewClient` ленивый, как `GrpcChannel.ForAddress`: один канал на зависимость на весь процесс.
- Ошибка — не `RpcException`, а значение `error`: `status.Code(err)`.

---

## Стримы, metadata, дедлайны

- `stream` в контракте — поток сообщений поверх одного HTTP/2-стрима; конец потока — `io.EOF` из `Recv`.
- Metadata — заголовки HTTP/2. Входящая и исходящая не смешиваются: токен клиента сам к соседу не уйдёт.
- Дедлайн `context.WithTimeout` уходит в `grpc-timeout` и становится `ctx.Deadline()` сервера.
- `context.Background()` в обработчике обрывает цепочку отмены.

---

## Статусы и ошибки

- Статус — код из 17 значений, сообщение и детали `errdetails` (`BadRequest`, `ErrorInfo`, `RetryInfo`).
- Код — контракт с клиентом: по нему решают, повторять ли вызов.
- Доменные ошибки переводятся в статус в одном месте; сырая ошибка наружу не уходит.

## Interceptors — middleware gRPC

```go
srv := grpc.NewServer(
	grpc.ChainUnaryInterceptor(logging, recovery, auth),
	// стримы идут мимо auth и recovery
)
```

Звено получает уже десериализованное сообщение, имя метода и `handler` — остаток цепочки. Для стримов нужна отдельная `ChainStreamInterceptor`.

## Эксплуатация и безопасность

- Health — стандартный `grpc.health.v1`, его понимают Kubernetes, Envoy и grpcurl. Reflection в проде выключают.
- TLS проверяет сервер, mTLS — клиента; токен — в metadata через `PerRPCCredentials`.
- grpc-gateway генерирует REST из аннотаций `google.api.http`. `Register…HandlerServer` обходит interceptors.
- `pick_first` и ClusterIP отправляют всю нагрузку в один под.

## Что запомнить

- Номер поля — навсегда; удалённое поле — в `reserved`.
- Один `*grpc.ClientConn` на зависимость, дедлайн — из входящего `ctx`.
- Сквозные задачи — interceptors, и для unary, и для стримов.
- `InsecureSkipVerify` — не способ «чтобы заработало».
