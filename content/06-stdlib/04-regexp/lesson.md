Регулярные выражения в Go — пакет `regexp` на движке RE2. Главное отличие от .NET: поиск гарантированно идёт за время, линейное от длины входа. Никакой шаблон и никакая строка не подвесят сервис катастрофическим бэктрекингом, поэтому `regexp` безопасно применять к пользовательскому вводу. Цена — нет обратных ссылок `\1`, lookahead и lookbehind `(?=…)`, `(?<=…)`, атомарных групп.

API выглядит громоздко, но собран из правил: `Find` — первое совпадение, `FindAll` — все; суффикс `String` — работа со строками вместо `[]byte`; `Submatch` — вместе с группами; `Index` — позиции вместо текста. Отсюда `FindAllStringSubmatchIndex` и прочие 16 комбинаций.

## Как это в C#

- `System.Text.RegularExpressions` по умолчанию — движок с бэктрекингом: умеет всё, но на неудачном шаблоне работает экспоненциально, поэтому существует `matchTimeout`. `RegexOptions.NonBacktracking` (.NET 7+) — тот же компромисс, что у RE2: линейное время без lookaround и обратных ссылок.
- `new Regex(..., RegexOptions.Compiled)` в статическом поле или `[GeneratedRegex]` (.NET 7+) → `var re = regexp.MustCompile(...)` на уровне пакета. Компилировать выражение в каждом вызове функции — заметная потеря времени.
- `Match.Groups["year"].Value` → `m[re.SubexpIndex("year")]`. Синтаксис именованных групп — `(?P<year>…)`, с Go 1.22 также `(?<year>…)`.
- `Regex.Replace(s, MatchEvaluator)` получает `Match` с группами. `ReplaceAllStringFunc` получает только строку совпадения — группы придётся выделить заново.

## Ловушки

### `$1x` в строке замены

```go
re := regexp.MustCompile(`(\w+)@(\w+)`)
re.ReplaceAllString("ann@mail", "$1x")   // "" — группы с именем «1x» нет
re.ReplaceAllString("ann@mail", "${1}x") // "annx"
```

После `$` берётся самое длинное имя из букв, цифр и `_`. Ставьте фигурные скобки. А если замена — данные, а не шаблон, используйте `ReplaceAllLiteralString`: там `$` ничего не значит.

### Совпадение не со всей строкой

```go
re := regexp.MustCompile(`\d+`)
re.MatchString("abc123") // true — нашлось внутри
```

`MatchString` ищет совпадение в любом месте. Для проверки формата добавляйте якоря: `^\d+$`. Учтите, что `$` без флага `(?m)` означает конец текста, а не строки.

### Компиляция в цикле

```go
for _, line := range lines {
	if regexp.MustCompile(`^\s*#`).MatchString(line) { // компиляция на каждой итерации
		continue
	}
}
```

Выражение не кешируется автоматически, как статические методы `Regex.IsMatch` в .NET. Выносите его в переменную пакета — `*regexp.Regexp` безопасен для одновременного использования из нескольких горутин.

## Задание

Напишите две функции для подстановки переменных в текст вида `Привет, ${name}!`.

Плейсхолдер — это `${имя}`, где имя начинается с латинской буквы или `_`, а дальше идут латинские буквы, цифры и `_`. Всё прочее — `${1x}`, `${}`, `$name`, `${a-b}` — плейсхолдером не считается и остаётся в тексте как есть.

`func Expand(s string, vars map[string]string) string`:

- каждый плейсхолдер, имя которого есть в `vars`, заменяется значением (в том числе пустым);
- плейсхолдеры с неизвестными именами остаются без изменений; `vars == nil` — ничего не заменяется;
- значение вставляется буквально: `$` и `${…}` внутри значения не интерпретируются и повторно не раскрываются.

`func Vars(s string) []string`:

- возвращает имена всех плейсхолдеров в порядке первого появления, без повторов;
- если плейсхолдеров нет — срез длины 0.
