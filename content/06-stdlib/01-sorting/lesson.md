В Go нет LINQ и `OrderBy`. Сортируют функциями пакета `slices`: `slices.Sort` — для чисел и строк, `slices.SortFunc` — со своей функцией сравнения. Обе работают **на месте**: меняют порядок элементов в переданном срезе и ничего не возвращают.

Функция сравнения возвращает `int` в стиле `IComparer<T>.Compare`: меньше нуля, ноль, больше нуля. Готовые кирпичики — в пакете `cmp`: `cmp.Compare(a, b)` сравнивает два значения, а `cmp.Or(...)` возвращает первый ненулевой результат — так собирается сортировка по нескольким ключам.

## Как это в C#

- `OrderBy` ленив и создаёт новую последовательность, исходная коллекция не меняется. `slices.Sort` и `slices.SortFunc` сортируют сам срез — как `List<T>.Sort()` или `Array.Sort()`. Нужна отсортированная копия — сначала `slices.Clone`.
- `OrderBy(x => x.A).ThenByDescending(x => x.B)` → одна функция сравнения: `cmp.Or(cmp.Compare(a.A, b.A), cmp.Compare(b.B, a.B))`. Убывание — аргументы в обратном порядке.
- `OrderBy` в LINQ устойчив, а `List<T>.Sort` — нет. В Go то же разделение: `SortFunc` неустойчив, `SortStableFunc` устойчив.
- `List<T>.BinarySearch` возвращает отрицательное число (`~index`), если элемент не найден. `slices.BinarySearch` возвращает позицию вставки и отдельный `bool`.

## Ловушки

### Сортировка меняет чужой срез

```go
func top3(scores []int) []int {
	slices.Sort(scores) // переставили элементы в срезе вызывающего!
	return scores[len(scores)-3:]
}
```

Срез — ссылка на общий массив, поэтому вызывающий код увидит свой срез отсортированным. Если функция не должна менять аргумент, сортируйте копию: `s := slices.Clone(scores)`.

### Вычитание вместо `cmp.Compare`

```go
slices.SortFunc(xs, func(a, b int64) int { return int(a - b) })
```

`a - b` переполняется на больших по модулю значениях и меняет знак, а приведение `int64` к `int` на 32-битных платформах ещё и обрезает старшие биты. Сортировка тихо выдаст неверный порядок. `cmp.Compare` сравнивает, а не вычитает, поэтому не переполняется; для чисел с плавающей точкой он ещё и ставит `NaN` раньше всех остальных, сохраняя корректный порядок.

### Двоичный поиск не по тому порядку

```go
slices.SortFunc(users, byNameDesc)
i, ok := slices.BinarySearchFunc(users, "Анна", byNameAsc) // мусор
```

Двоичный поиск верен, только если срез отсортирован тем же сравнением, которым ищем. Иначе результат не определён — ошибки не будет, просто неверный ответ.

## Задание

Напишите функцию `Leaderboard(players []Player) []Player`, которая возвращает таблицу лидеров.

```go
type Player struct {
	Name  string
	Score int // очки
	Time  int // время прохождения в секундах
}
```

Требования:

- игроки упорядочены по `Score` по убыванию;
- при равных очках выше тот, у кого меньше `Time`;
- при равных очках и времени — по `Name` по возрастанию (обычное сравнение строк);
- функция возвращает **новый** срез, исходный `players` не меняется — ни порядок, ни элементы;
- для пустого или `nil` входа возвращается срез длины 0.
