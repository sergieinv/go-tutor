Окружение процесса — набор строк `KEY=value`. `os.Getenv` читает значение, `os.LookupEnv` дополнительно сообщает, задана ли переменная вообще, `os.Setenv`/`os.Unsetenv` меняют окружение текущего процесса, `os.Environ` возвращает его целиком. Для подстановки в строки есть `os.ExpandEnv` и `os.Expand`.

Стандартной «системы конфигурации» в Go нет: загрузчик настроек — обычная функция, которая читает переменные, подставляет значения по умолчанию и разбирает типы через `strconv` и `time.ParseDuration`. Ошибки разбора — обычные ошибки, а не исключения при старте хоста.

## Как это в C#

- `Environment.GetEnvironmentVariable` возвращает `null` для незаданной переменной и `""` для пустой. В Go `Getenv` даёт `""` в обоих случаях — различает их только `LookupEnv`.
- `IConfiguration` в ASP.NET Core собирает настройки из нескольких источников и привязывает их к классам (`APP__DB__HOST` → `App:Db:Host`). В Go это пишется руками или берётся из сторонних библиотек вроде `envconfig`.
- `Environment.ExpandEnvironmentVariables("%HOME%")` → `os.ExpandEnv("$HOME")`, но синтаксис Unix: `$VAR` и `${VAR}`. Незаданная переменная в Go заменяется пустой строкой, в .NET остаётся как есть.
- В тестах .NET окружение меняют вручную и возвращают в `finally`. В Go `t.Setenv` делает это сам и восстанавливает значение после теста.

## Ловушки

### `Getenv` не отличает «пусто» от «не задано»

```go
// APP_PREFIX="" — пользователь явно хочет пустой префикс
prefix := os.Getenv("APP_PREFIX")
if prefix == "" {
	prefix = "app-" // а мы подставили значение по умолчанию
}
```

Если пустое значение что-то значит, используйте `v, ok := os.LookupEnv(key)` и подставляйте значение по умолчанию только при `!ok`.

### Окружение — общее состояние процесса

```go
func TestA(t *testing.T) {
	os.Setenv("APP_MODE", "test") // утечёт в другие тесты пакета
}
```

`os.Setenv` меняет окружение всего процесса, без отката. В тестах используйте `t.Setenv`: он восстановит прежнее значение (или удалит переменную) после теста. Платой за это — запрет на `t.Parallel()` в таком тесте: вызов паникует.

### `ExpandEnv` и знак доллара в данных

```go
os.ExpandEnv("price: $5, pass: p$ss") // "price: , pass: p"
```

`ExpandEnv` подставляет всё, что похоже на переменную, а незаданные молча заменяет пустой строкой. Не прогоняйте через него произвольные строки, пароли или шаблоны с `$`.

## Задание

Напишите загрузку конфигурации сервиса из окружения:

```go
type Config struct {
	Addr    string        // APP_ADDR, по умолчанию ":8080"
	Debug   bool          // APP_DEBUG, по умолчанию false
	Timeout time.Duration // APP_TIMEOUT, по умолчанию 5s
	Workers int           // APP_WORKERS, по умолчанию 4
	Tags    []string      // APP_TAGS, по умолчанию []string{"default"}
}

func Load() (Config, error)
```

Требования:

- для `APP_ADDR`, `APP_DEBUG`, `APP_TIMEOUT`, `APP_WORKERS` пустое значение равносильно отсутствию переменной — берётся значение по умолчанию;
- `APP_DEBUG` разбирается `strconv.ParseBool`, `APP_TIMEOUT` — `time.ParseDuration` (должен быть больше нуля), `APP_WORKERS` — `strconv.Atoi` (должен быть больше нуля);
- `APP_TAGS` — список через запятую; у элементов обрезаются пробелы, пустые элементы отбрасываются. Если переменная **не задана**, `Tags` — `[]string{"default"}`; если задана, но пустая (или из одних запятых и пробелов), — пустой список (`nil` допустим);
- если значение не разбирается или вне допустимого диапазона, `Load` возвращает нулевой `Config{}` и ошибку, текст которой содержит имя переменной (например, `APP_WORKERS: ...`); если неверных переменных несколько, достаточно сообщить об одной.
