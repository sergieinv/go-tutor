`os.WriteFile(name, data, perm)` записывает срез байт целиком: создаёт файл или обрезает существующий. Для потоковой записи файл открывают через `os.Create` или `os.OpenFile` с флагами (`O_APPEND`, `O_CREATE`, `O_EXCL`, `O_TRUNC`) и пишут в него как в любой `io.Writer` — `fmt.Fprintf`, `io.Copy`, `json.NewEncoder(f)`.

Запись сложнее чтения тем, что у неё больше способов потерять данные: не сброшенный буфер, проигнорированная ошибка `Close`, программа, упавшая на середине файла. Урок — про то, как этих потерь избежать.

## Как это в C#

- `File.WriteAllBytes`/`WriteAllText` → `os.WriteFile`. `File.AppendAllText` → `OpenFile` с `O_APPEND|O_CREATE|O_WRONLY`. `FileMode.CreateNew` → `O_CREATE|O_EXCL`.
- Права доступа задаются при создании числом в стиле Unix: `0o644` — владельцу чтение и запись, остальным чтение. Итоговые права урезает umask процесса. В .NET права обычно не указывают вовсе, хотя с .NET 7 есть `File.SetUnixFileMode` и `FileStreamOptions.UnixCreateMode`.
- `StreamWriter` сбрасывает буфер в `Dispose`. У `bufio.Writer` нет `Close` — `Flush` вызывают явно, иначе хвост данных пропадёт.
- Ошибку сброса при закрытии `Dispose` в .NET бросает исключением. В Go `Close() error` её возвращает, и `defer f.Close()` её молча теряет — при записи её надо проверить явно. Атомарной замене `File.Replace`/`File.Move(..., overwrite: true)` соответствует `os.Rename`.

## Ловушки

### Забытый `Flush`

```go
w := bufio.NewWriter(f)
fmt.Fprintln(w, "hello")
f.Close() // буфер не сброшен — файл пустой
```

`bufio.Writer` отдаёт данные файлу, только когда буфер заполнится (4 КБ по умолчанию) или при `Flush`. Короткий вывод так и остаётся в памяти. Вызывайте `w.Flush()` и проверяйте его ошибку — в ней же окажутся ошибки всех предыдущих записей.

### `defer f.Close()` при записи

```go
f, _ := os.Create(path)
defer f.Close() // ошибка потеряна
_, err := f.Write(data)
return err
```

Файловая система может сообщить об ошибке (переполнение диска, сетевой том) только при закрытии. Для записи закрывайте явно и возвращайте ошибку `Close` — или через именованный результат в отложенном замыкании, как в уроке про `defer`.

### Перезапись на месте

```go
os.WriteFile("config.json", data, 0o644) // O_TRUNC: сначала файл обнуляется
```

Если процесс упадёт посередине, останется пустой или обрезанный файл, а параллельный читатель может увидеть половину. Пишите во временный файл **в том же каталоге** и заменяйте целевой через `os.Rename` — в пределах одной файловой системы на Unix это атомарно. Между разными файловыми системами `Rename` не работает, поэтому `os.TempDir()` для временного файла не годится.

## Задание

Напишите функцию атомарной записи файла:

```go
func WriteAtomic(path string, write func(w io.Writer) error) error
```

`write` пишет содержимое файла — возможно, множеством мелких вызовов. Требования:

- данные пишутся во временный файл в том же каталоге, что и `path` (`os.CreateTemp`), через `bufio.Writer`; после успешной записи временный файл переименовывается в `path`, заменяя существующий файл;
- итоговый файл имеет права ровно `0o644` (у файла от `os.CreateTemp` права `0o600`, umask на `Chmod` не влияет);
- если `write`, `Flush`, `Close`, `Chmod` или `Rename` вернули ошибку, `WriteAtomic` возвращает ошибку, для которой `errors.Is` находит исходную; временный файл удаляется, а прежний файл по адресу `path` (если был) остаётся нетронутым;
- после успешного вызова в каталоге не остаётся временных файлов — только `path`;
- если каталога `path` не существует, возвращается ошибка, `write` не вызывается и ничего не создаётся.
