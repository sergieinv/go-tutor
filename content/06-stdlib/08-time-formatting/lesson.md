Самое странное в пакете `time` для новичка — форматные строки. Вместо `yyyy-MM-dd HH:mm` Go просит написать, как выглядела бы **эталонная дата** — 2 января 2006 года, 15:04:05, пояс MST (−07:00): `2006-01-02 15:04`. Числа подобраны так, чтобы их было легко запомнить: месяц 1, день 2, час 3 (или 15), минута 4, секунда 5, год 6, пояс −7.

Раскладка (layout) работает в обе стороны: `t.Format(layout)` печатает момент, `time.Parse(layout, s)` разбирает строку. Всё, что в раскладке не совпало с кусками эталона, копируется как есть — поэтому опечатка в раскладке не даёт ошибку, а молча печатает не то.

## Как это в C#

- `ToString("yyyy-MM-dd HH:mm")` → `Format("2006-01-02 15:04")`; `"dd.MM.yyyy"` → `"02.01.2006"`; `".fff"` → `".000"`; `"zzz"` → `"-07:00"`; `"hh"`/`"tt"` → `"03"`/`"PM"`.
- `"o"` (round-trip) → `time.RFC3339Nano`; `"s"` → `"2006-01-02T15:04:05"` (с пробелом вместо `T` — готовая константа `time.DateTime`). Культур нет: имена месяцев и дней — только английские.
- `DateTime.ParseExact` → `time.Parse`. Если в строке нет смещения, C# вернёт `DateTimeKind.Unspecified`, а `Parse` считает её UTC. Нужен конкретный пояс — `ParseInLocation`.
- `DateTimeOffset.ToUnixTimeSeconds`/`FromUnixTimeMilliseconds` → `t.Unix()`, `t.UnixMilli()`, `time.Unix(sec, nsec)`, `time.UnixMilli(ms)`.

## Ловушки

### Раскладка в стиле C# не даёт ошибки

```go
t.Format("yyyy-MM-dd") // "yyyy-MM-dd" — ни одного куска эталона
t.Format("2006-02-01") // год-ДЕНЬ-месяц: 02 — это день
```

`Format` не знает, что вы имели в виду, и не проверяет раскладку. Пишите её от эталона и проверяйте тестом на дате, где день больше 12.

### `Parse` без смещения — это UTC

```go
t, _ := time.Parse("2006-01-02 15:04", "2024-03-05 10:00")
fmt.Println(t) // 2024-03-05 10:00:00 +0000 UTC
```

Строка «10:00» от пользователя из Москвы превратится в 10:00 UTC — на три часа позже. Время без смещения разбирайте через `ParseInLocation` с поясом пользователя.

### Миллисекунды в `time.Unix`

```go
ms := int64(1_700_000_000_123)
t := time.Unix(ms, 0) // год 55 841 — это были миллисекунды
t = time.UnixMilli(ms) // 2023-11-14
```

JavaScript и многие API отдают миллисекунды. `time.Unix` ждёт секунды и ошибку не вернёт.

## Задание

Напишите функции для разбора дат из разных источников и вывода их пользователю.

`func ParseFlexible(s string, loc *time.Location) (time.Time, error)` пробует раскладки по порядку и возвращает результат первой подошедшей:

1. `time.RFC3339` — строка со смещением, например `2024-03-05T10:00:00+03:00` или `2024-03-05T07:00:00Z`; `loc` не используется;
2. `2006-01-02 15:04:05` — в поясе `loc`;
3. `2006-01-02` — полночь в поясе `loc`;
4. `02.01.2006` — полночь в поясе `loc`.

Требования:

- для раскладок 2–4 результат находится в поясе `loc` (`t.Location() == loc`); если `loc == nil` — в `time.UTC`;
- строка разбирается как есть: пробелы по краям, несуществующие даты (`2024-02-30`) и любые другие форматы — ошибка;
- при ошибке возвращается нулевое `time.Time` и ненулевая ошибка.

`func FormatHuman(t time.Time) string` возвращает время в собственном поясе `t` в виде `05.03.2024 15:04 +03:00` (для UTC — `+00:00`).
