Маленький файл читают одним вызовом `os.ReadFile` — получается `[]byte`. Большой или потоковый открывают через `os.Open` и читают по частям: построчно через `bufio.Scanner`, до разделителя через `bufio.Reader`, целиком через `io.ReadAll`.

Все эти инструменты работают не с файлом, а с интерфейсом `io.Reader` — одним методом `Read(p []byte) (n int, err error)`. Поэтому функции обработки принято объявлять с параметром `io.Reader`: в программе им передают `*os.File`, в тестах — `strings.NewReader`.

## Как это в C#

- `File.ReadAllText` / `ReadAllBytes` — это `os.ReadFile`. Отдельного «читать как строку» нет: `string(data)` превращает байты в строку без перекодировки, файл считается UTF-8.
- `Stream` — абстрактный класс с десятком методов; `io.Reader` — интерфейс из одного метода. Возможности добавляются другими маленькими интерфейсами: `io.Closer`, `io.Seeker`, `io.ReaderAt`.
- `StreamReader.ReadLine()` → `bufio.Scanner`. Но у сканера есть предел длины строки (по умолчанию 64 КБ), а у `ReadLine` — нет.
- `using var f = File.OpenRead(p)` → `f, err := os.Open(p)` + `defer f.Close()`. Отсутствие файла — не исключение, а ошибка, проверяемая через `errors.Is(err, fs.ErrNotExist)`.

## Ловушки

### Ошибку `Scanner` проверяют после цикла

```go
for sc.Scan() {
	process(sc.Text())
}
// без этой проверки обрыв чтения выглядит как конец файла
if err := sc.Err(); err != nil {
	return err
}
```

`Scan` возвращает `false` и в конце файла, и при ошибке. Различить их можно только через `sc.Err()` — он равен `nil`, если файл просто кончился.

### Строка длиннее 64 КБ

```go
sc := bufio.NewScanner(f)
for sc.Scan() { /* ... */ } // остановится на длинной строке
fmt.Println(sc.Err())       // bufio.Scanner: token too long
```

Минифицированный JSON или строка лога легко превышают `bufio.MaxScanTokenSize`. Сканер молча прекращает чтение, и если не проверить `Err`, остаток файла теряется. Поднимите лимит: `sc.Buffer(make([]byte, 0, 64*1024), 10<<20)` — до первого `Scan`. Для строк неограниченной длины используйте `bufio.Reader.ReadString('\n')`.

### `Read` может вернуть данные вместе с ошибкой

```go
n, err := r.Read(buf)
if err != nil {
	return err // а n байт в buf уже прочитаны и потеряны
}
```

Контракт `io.Reader` разрешает вернуть `n > 0` и `io.EOF` одновременно. Сначала обработайте `buf[:n]`, потом смотрите на ошибку. А лучше не вызывайте `Read` руками: `io.ReadAll`, `io.Copy`, `bufio.Scanner` уже делают это правильно.

## Задание

Напишите разбор простого конфигурационного файла формата `ключ = значение`.

```go
func Parse(r io.Reader) (map[string]string, error)
func Load(path string) (map[string]string, error)
```

Требования к `Parse`:

- вход читается построчно; окончания строк — `\n` или `\r\n`;
- пустые строки (в том числе из одних пробелов) и строки, которые после обрезки пробелов начинаются с `#`, пропускаются;
- остальные строки делятся по **первому** `=`: слева ключ, справа значение (значение само может содержать `=`); у ключа и значения обрезаются пробельные символы по краям (`strings.TrimSpace`);
- пустое значение допустимо (`key =` → `""`); строка без `=` или с пустым ключом — ошибка, текст которой начинается с `line N: `, где `N` — номер строки во входе, считая с 1 и включая пропущенные строки;
- если ключ повторяется, побеждает последнее значение;
- строки длиной до 1 МиБ (1 048 576 байт) должны читаться;
- ошибка чтения из `r` возвращается так, чтобы `errors.Is` находил исходную ошибку;
- при любой ошибке возвращается `nil`-карта; для пустого входа — пустая, но не `nil` карта и `nil`-ошибка.

`Load` открывает файл `path`, разбирает его через `Parse` и закрывает. Если файла нет, ошибка должна удовлетворять `errors.Is(err, fs.ErrNotExist)`.
