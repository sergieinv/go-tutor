Для писем, конфигов, генерации кода и отчётов в Go есть шаблонизатор в стандартной библиотеке — `text/template`. Шаблон — обычный текст с действиями в `{{ }}`: `{{.Name}}` подставляет поле, `{{range}}` повторяет блок, `{{if}}` и `{{with}}` выбирают ветку. Точка `.` — «текущие данные»: в начале это аргумент `Execute`, внутри `range` и `with` — текущий элемент.

Шаблон разбирается один раз (`Parse`) и исполняется сколько угодно раз (`Execute`) с разными данными, в любой `io.Writer`. Шаблоны не компилируются вместе с программой: опечатка в имени поля обнаружится только при исполнении — как ошибка, а не паника.

## Как это в C#

- Интерполяция `$"..."` проверяется компилятором и не годится для шаблонов, которые хранят отдельно. Ближе всего к `text/template` — Scriban или Handlebars.NET: шаблон — данные, поля ищутся по имени через рефлексию. Razor устроен иначе: шаблон компилируется в C# и проверяется типами.
- В Razor внутри `@{ }` можно писать любой C#. Язык шаблонов Go намеренно беден: поля, методы без побочных эффектов, `if`/`range`/`with`, встроенные `len`, `index`, `printf`, `eq`/`lt`/`and`/`or`/`not`. Всё остальное — свои функции через `FuncMap`.
- Razor экранирует HTML по умолчанию. `text/template` не экранирует ничего, для HTML есть отдельный `html/template` с тем же API: он понимает контекст (текст, атрибут, URL, JavaScript) и экранирует по нему.
- Аналога `@section` и layout нет, но есть именованные шаблоны: `{{define "name"}}...{{end}}` и вызов `{{template "name" .}}`.

## Ловушки

### Конвейер передаёт значение последним аргументом

```go
funcs := template.FuncMap{"join": strings.Join} // join(elems, sep)
// {{.Tags | join ", "}} — это join(", ", .Tags): ошибка типов при Execute
```

`x | f a b` вызывает `f(a, b, x)`. Функции, удобные в конвейере, принимают «главный» аргумент последним: `func(sep string, items []string) string`.

### Частичный вывод при ошибке

```go
err := t.Execute(w, data) // в w уже записано начало шаблона
```

`Execute` пишет в `w` по мере исполнения и останавливается на ошибке — получатель увидит обрезанный текст. Если частичный результат недопустим (HTTP-ответ, файл), исполняйте в `bytes.Buffer` и копируйте его только при `err == nil`.

### Отсутствующий ключ map — не ошибка

```go
t := template.Must(template.New("").Parse("{{.Name}}"))
t.Execute(os.Stdout, map[string]string{}) // <no value>
```

Для структуры неизвестное поле — ошибка исполнения, а для map — пустое значение, которое печатается как `<no value>`. Строгий режим включается опцией `t.Option("missingkey=error")`. Неэкспортируемые поля структур шаблону не видны вовсе.

## Задание

Напишите функцию `Render(text string, data any) (string, error)`, которая разбирает шаблон `text` и исполняет его с данными `data`.

Требования:

- в шаблоне доступны три функции:
  - `upper` — `strings.ToUpper` для строки: `{{.Name | upper}}`;
  - `join` — соединяет срез строк через разделитель; разделитель — первый аргумент, срез — второй, чтобы работал конвейер: `{{.Tags | join ", "}}`;
  - `default` — `{{.Nick | default "аноним"}}` возвращает значение, если это непустая строка, иначе запасное значение (первый аргумент); оба аргумента — строки;
- если в данных-map нет ключа, к которому обращается шаблон, это ошибка (`missingkey=error`);
- при ошибке разбора или исполнения функция возвращает пустую строку и ненулевую ошибку — никакого частичного вывода;
- без ошибок — весь результат исполнения и `nil`.
