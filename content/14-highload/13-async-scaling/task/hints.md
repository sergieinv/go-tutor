## Подсказка 1

Состояние проекции: `map[string]*OrderView` применённых заказов, `map[string]map[int]Event` отложенных событий (заказ → номер → событие), `Stats` и один `sync.Mutex`, которым закрыты все методы. Проверку формата события делайте до блокировки и до любых изменений — плохое событие не должно трогать ни модель, ни счётчики.

## Подсказка 2

В `Apply` под блокировкой три ветки по номеру. `last` — `Seq` заказа из модели или 0:

```go
switch {
case e.Seq <= last || isPending(e.OrderID, e.Seq):
	p.stats.Duplicates++
case e.Seq > last+1:
	// положить в pending[e.OrderID][e.Seq], Pending++
default:
	// применить, затем вытащить следующих из pending
}
```

## Подсказка 3

После применения события с номером `n` проверяйте `pending[order][n+1]` в цикле: есть — удалить из отложенных (`Pending--`), применить, перейти к `n+1`. `Order` и `ByCustomer` возвращают значения `OrderView` (`*v`), а не указатели из map — тогда изменение результата не тронет проекцию. `ByCustomer` сортируйте `slices.SortFunc` по `OrderID`: порядок обхода map случаен.
