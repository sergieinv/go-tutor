## Подсказка 1

Всё состояние — под одним `sync.Mutex`: счётчики `Stats` и очередь ждущих вызовов. Ждущий вызов — это канал, который закроют, когда ему передадут место. Очередь — `container/list` (удалять из середины при таймауте) или срез. Решение «сразу / в очередь / отказ» принимается целиком под мьютексом, а `fn` выполняется без него.

## Подсказка 2

Освобождая место после `fn`, не уменьшайте `InFlight`, если очередь не пуста: снимите первого ждущего, закройте его канал и посчитайте его в `Accepted` — место переходит к нему из рук в руки. Тогда новый вызов не обгонит очередь, а FIFO получится само. Быстрый путь — только когда `InFlight < N` **и** очередь пуста.

## Подсказка 3

Ожидание в очереди:

```go
select {
case <-w.ready:
	return l.run(ctx, fn)
case <-l.cfg.After(l.cfg.QueueTimeout):
	// под мьютексом: если w.ready уже закрыт — место наше, выполняем fn;
	// иначе убрать w из очереди, Queued--, TimedOut++ и вернуть ErrQueueTimeout
case <-ctx.Done():
	// то же, но Canceled++ и ctx.Err()
}
```

Проверка «уже закрыт» — неблокирующий `select { case <-w.ready: ... default: }` под тем же мьютексом, под которым место передаётся.
